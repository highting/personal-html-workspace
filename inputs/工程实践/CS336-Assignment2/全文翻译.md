端到端基准测试
原文 §2.1.3，p3–4。

现在，我们将实现一个简单的性能评估脚本。我们会测试模型的许多变体，例如改变精度、替换层等，因此，让脚本能够通过命令行参数启用这些变体会很值得，这样后续运行就会更方便。

首先，对模型进行最简单的性能分析：测量前向传播、反向传播和优化器更新的时间。因为我们只测量速度和显存，所以可以使用随机权重和随机数据。

性能测量需要注意一些细节：常见的陷阱可能让我们没有测到真正想测的东西。对 GPU 代码做基准测试时，需要注意 CUDA 调用是异步的。调用 CUDA 内核时，例如调用 torch.matmul，PyTorch 函数会在矩阵乘法完成之前把控制权返回给你的代码。这样，在 GPU 完成矩阵乘法的同时，CPU 可以继续向前执行并调度新的操作，这对性能很有好处。

另一方面，这也意味着，简单测量 torch.matmul 从调用到返回所花的时间，并不能告诉你 GPU 实际完成矩阵乘法所需的时间。在 PyTorch 中，可以调用 torch.cuda.synchronize() 等待所有已经调度的 GPU 内核完成，从而更准确地测量 CUDA 内核运行时间。这个操作中的同步，是指 CPU 运行时与 GPU 运行时之间的同步。记住这一点，接下来编写基本的性能分析基础设施。

Nsight Systems 性能分析器
原文 §2.1.4，p4–6。

端到端基准测试不会告诉我们模型在前向与反向传播的哪些地方消耗时间和显存，因此也无法揭示具体优化机会。要了解程序在每个组件，例如某个函数中花了多少时间，可以使用性能分析器。执行性能分析器会在函数开始和结束时插入监测代码，从而提供详细的函数级执行统计，例如调用次数、平均耗时、该函数累计耗时等。

标准 Python 性能分析器，例如 CProfile，无法分析 CUDA 内核，因为这些内核在 GPU 上异步执行。幸运的是，NVIDIA 提供了可以通过命令行 nsys 使用的性能分析器。我们建议从包管理器或其下载页面安装较新的版本。在这部分作业中，你将使用 nsys 分析 Transformer 模型的运行时间。

nsys 的使用很简单：在上一节的 Python 脚本命令前加上 nsys profile。例如，对 benchmark.py 做基本分析：

$ uv run nsys profile -- python benchmark.py
然后，可以在本地计算机上使用 NVIDIA Nsight Systems 桌面应用查看结果。在分析视图的 CUDA API 行中选中某个 CPU 上的 CUDA API 调用，会高亮显示 CUDA HW 行中与之对应的全部 GPU 内核执行。

一次更全面的分析可能如下：

$ uv run nsys profile --trace=cuda,cudnn,cublas,osrt,nvtx --pytorch=functions-trace,autograd-shapes-nvtx --cudabacktrace=all --python-backtrace=cuda --gpu-metrics-devices=0 -- python benchmark.py

在这个例子中，--trace 指定要记录哪些 API；--pytorch 会在模块调用与 autograd 过程中插入 NVTX 标签；--cudabacktrace 和 --python-backtrace 提供更完整的调用栈，帮助理解某个内核从你的哪段代码发起；--gpu-metrics-devices 指定要测量哪张 GPU 的利用率。

加入性能分析并非没有代价，它会让整体运行变慢。通常只启用本次运行真正需要的功能更合适。特别是，在不需要调用栈时，可以移除 --cudabacktrace=all 和 --python-backtrace=cuda，因为它们的额外开销很大。

我们鼓励你尝试 nsys profile 的各种命令行选项，了解它的能力。也可以使用 NVTX range 标注代码；它们会在分析结果的 NVTX 行中显示为块，覆盖其中的全部 CUDA API 调用及相关内核执行。尤其应该使用 NVTX range 排除基准脚本中的预热步骤，具体方式是在分析时对 NVTX 标签应用 --nvtx-capture 过滤器。

混合精度
原文 §2.1.5，p7–9。

到目前为止，我们一直使用 FP32 精度：所有模型参数和激活的数据类型都是 torch.float32。不过，现代 NVIDIA GPU 包含专门用于加速低精度矩阵乘法的 GPU 核心，即 Tensor Core。例如，NVIDIA B200 的规格表显示，FP32 的最大吞吐为 80 TFLOPS，而 FP16，即半精度浮点数，或 BF16，即 bfloat16，的最大吞吐要高得多，达到 2500 TFLOPS。因此，使用较低精度的数据类型应有助于加速训练和推理。

然而，直接把模型转换成低精度格式，可能会降低模型准确性。例如，实践中很多梯度值太小，FP16 无法表示，直接使用 FP16 训练时它们会变成零。为了解决这个问题，FP16 训练通常使用 loss scaling：将损失乘以一个缩放因子，提高梯度的量级，使它们不至于下溢为零。此外，FP16 的动态范围小于 FP32，可能出现溢出，表现为损失变成 NaN。完全使用 bfloat16 训练通常更加稳定，因为 BF16 与 FP32 的动态范围相同，但相较于 FP32，最终模型性能仍可能受影响。

为了利用低精度的加速优势，人们通常使用混合精度训练。PyTorch 通过 torch.autocast 上下文管理器实现这一点：部分操作，例如矩阵乘法，使用较低精度；另一些需要 FP32 完整动态范围的操作，例如累加和归约，则保持原样。下面的代码会自动识别前向中哪些操作应使用较低精度，并将这些操作转换为指定类型：

model: torch.nn.Module = ...  # 例如，你的 Transformer 模型
dtype: torch.dtype = ...      # 例如 torch.bfloat16
x: torch.Tensor = ...         # 输入数据
with torch.autocast(device_type="cuda", dtype=dtype):
    y = model(x)
正如前面暗示的，即使被累加的张量已经转换为低精度，通常仍应使用较高精度进行累加。下面的练习将帮助你建立直觉，理解原因。

题目：混合精度累加（mixed_precision_accumulation，1 分）
运行下面的代码，并评论结果的准确性。

s = torch.tensor(0, dtype=torch.float32)
for i in range(1000):
    s += torch.tensor(0.01, dtype=torch.float32)
print(s)

Autograd 残留张量
原文 §3.1，p10–12。

回忆一下，为了完成模型的反向传播，我们需要保存前向产生的激活。对于某些运算，这显而易见；但默认情况下，需要保存张量的运算可能比你想象的多得多。为反向保存的张量叫作“residuals”，也可以直接叫“saved tensors”。

让我们了解网络到底保存了什么。从一个看起来很普通的 RMSNorm 函数开始，为简单起见全部使用 FP32，在 autograd 保存或取回张量时添加钩子。

import torch
from torch import nn

x = torch.randn((4, 512, 2560), requires_grad=True)

class RMSNorm(nn.Module):
    def __init__(
        self,
        hidden_size: int,
        eps: float = 1e-5,
        device=None,
    ):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(hidden_size, device=device))
        self.eps = eps

    def forward(self, x):
        rms = torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        x = x * rms
        return self.weight * x

def pack_hook(t):
    shape, dtype, grad_fn = t.shape, t.dtype, t.grad_fn
    print(f"Saving residual: {shape=}, {dtype=}, {grad_fn=}")
    return t

def unpack_hook(t):
    shape, dtype, grad_fn = t.shape, t.dtype, t.grad_fn
    print(f"Loading residual: {shape=}, {dtype=}, {grad_fn=}")
    return t

ln = RMSNorm(x.shape[-1])
with torch.autograd.graph.saved_tensors_hooks(pack_hook, unpack_hook):
    y = ln(x)
    y.sum().backward()

重计算
原文 §3.2.1，p13–15。

不一定要一直持有每个生成的张量。可以只定期保存结果的检查点，再重新计算它们之间的值。PyTorch 提供了一个简单接口：torch.utils.checkpoint.checkpoint 接收一个函数及其参数，并改变该函数的行为：

前向传播时，保存函数的输入值，抑制前向内部张量的保存。
反向传播时，先增加一次重计算：从之前保存的输入重新执行前向，并保存反向需要的值；随后执行反向，所有这些张量都可以被释放。
在依次执行四个 TransformerBlock 的简单例子中，可以看到显存会如预期般累加。

    x = block(x)

不过，可以如下使用梯度检查点：

from torch.utils.checkpoint import checkpoint

def two_blocks(x):
    x = block(x)
    x = block(x)
    return x

def four_blocks_checkpoint(x):
    # checkpoint 会丢弃保存的张量，直到反向阶段。
    # 反向走到被 checkpoint 包裹的块时，
    # 它重新执行前向以产生所需张量，
    # 然后完成正常反向。
    x = checkpoint(two_blocks, x, use_reentrant=False)
    x = checkpoint(two_blocks, x, use_reentrant=False)
    return x

with torch.autograd.graph.saved_tensors_hooks(pack_hook, unpack_hook):
    y = four_blocks_checkpoint(x)
print(f"Total size of saved tensors in four TransformerBlocks with checkpointing: {total_size_bytes / (1024**2):.2f} MiB")

请记住，这并没有消除显存使用，而是把显存分成两类：一类是在每次 checkpoint 入口处，为重计算长期保存的存储，即检查点本身；另一类是在 checkpoint 包裹区域重算时，为其反向产生的短期内存。

由于主要关注的是峰值显存，我们需要在保存检查点的成本与物化一个完整 checkpoint 区域所需 residuals 的成本之间权衡。检查点越多，每个区域内部物化的内存越少，但检查点本身需要的内存越多。

在上面的例子中，重算 residuals 的显存显然占主导，部分原因是检查点很小，因此把平衡点进一步向检查点存储一侧移动会有益。也就是说，应缩小每个 checkpoint 包裹区域的范围。

checkpoint 区域大一些或小一些，不会影响重计算的计算成本。不过，可以通过递归检查点继续用计算换显存，即在一个 checkpoint 调用内部嵌套其他 checkpoint 调用。

补充答案（非原文；理论与预测）

(a) 需要区分“实用的平衡递归”与题目字面上的“不计计算成本”。平衡二分递归保留对数层数的边界激活，可达到激活空间约为 O(log N)、计算量 O(N log N)。如果允许为每一层 backward 都从最初输入重新计算其前缀，并及时释放中间激活，则只需常数个活跃激活与当前层 residual，关于 N 的激活空间可为 O(1)，而累计重算长度为：

$$ 0+1+\cdots+(N-1)=\frac{N(N-1)}2, $$

计算量为 O(N²)。这种极端调度忽略框架 bookkeeping，不能由任意嵌套写法自动保证。这里提供文字调用安排而不补作业实现；长期保留最初输入，逆序到某层时重建其输入，只保留该层反向所需 residual，完成后立即释放。

(b) 设单个边界激活大小 A、单 block residual 为 R，每段 k 层：

$$ M_{\mathrm{act}}(k)\approx\frac{NA}{k}+kR, \qquad k^\star\approx\sqrt{\frac{NA}{R}}. $$

你的性能分析很可能表明，attention 层在显存与计算两方面都有优化空间。从高层看，attention 包含一次矩阵乘法、一次 softmax，以及随后另一次矩阵乘法：

朴素 attention 实现需要为每个 batch/head 元素保存一个形状为 seq_len × seq_len 的分数矩阵。序列很长时，它会变得巨大，导致处理长输入或长输出的任务出现显存不足。我们将依据 FlashAttention-2 论文实现 attention 内核，按 tile 计算，始终避免显式物化整个 seq_len × seq_len 分数矩阵，从而支持长得多的序列。

示例：加权求和
原文 §4.2.1，p17–22。

为了介绍需要掌握的 Triton 知识，以及它如何与 PyTorch 配合，我们将完整展示一个“加权求和”运算的内核。更多 Triton 入门资料可参阅 Triton 教程。需要指出的是，这些教程没有使用新的、方便的 block pointer 抽象，下面我们将介绍它。

给定输入矩阵 X，将其元素乘以一个按列作用的权重向量 w，再对每行求和，就得到 X 与 w 的矩阵向量乘积。我们先介绍前向，再编写对应的 Triton 反向内核。

前向传播

内核前向就是下面的广播内积：

def weighted_sum(x, weight):
    # 假设 x 的 n 维形状为 [..., D]，weight 的一维形状为 [D]。
    return (weight * x).sum(axis=-1)
编写 Triton 内核时，每个 program instance，可以并行运行，计算 x 某个行 tile 的加权和，并把相应标量写入输出张量。在 Triton 中，一个 program instance 是一组执行同一程序的线程，这些 thread block 可以在 GPU 上并行运行。我们不传入张量，而是传入指向其首元素的指针，以及说明如何沿各个轴移动的 stride。

可以利用 stride，加载当前 instance 负责求和的 x 行 tile，并用 program ID 划分工作：第 i 个 instance 处理第 i 个行 tile。这个简单例子中，Triton 前向与 PyTorch 的主要差异是需要指针运算以及显式 load/store。我们使用 tl.make_block_ptr 提供的 block pointer 抽象来大幅简化指针运算，不过首先需要配置这些 block pointer。

import triton
import triton.language as tl

@triton.jit
def weighted_sum_fwd(
    x_ptr, weight_ptr,  # 输入指针
    output_ptr,        # 输出指针
    x_stride_row, x_stride_dim,  # stride 表示沿各轴移动一个元素的距离
    weight_stride_dim,           # 通常为 1
    output_stride_row,           # 通常为 1
    NUM_ROWS, D,
    ROWS_TILE_SIZE: tl.constexpr,
    D_TILE_SIZE: tl.constexpr,   # tile 形状必须在编译时已知
):
    # 每个 instance 计算 x 的一个行 tile 的加权和。
    # tl.program_id 告诉我们当前处于哪个 thread block。
    row_tile_idx = tl.program_id(0)

    # block pointer 允许选择一个 N 维内存区域，并移动该选择。
    # 它需要知道：
    # - 张量首元素的指针；
    # - 张量整体 shape，以处理越界；
    # - 各维 stride，以正确使用内存布局；
    # - 起始块的 N 维坐标，即 offsets；
    # - 一次加载/存储的 block shape；
    # - 内存维度由 major 到 minor 的顺序（= np.argsort(strides)），
    #   用于优化，并为 >=Hopper 上的 TMA 支持所需。
    x_block_ptr = tl.make_block_ptr(
        x_ptr,
        shape=(NUM_ROWS, D,),
        strides=(x_stride_row, x_stride_dim),
        offsets=(row_tile_idx * ROWS_TILE_SIZE, 0),
        block_shape=(ROWS_TILE_SIZE, D_TILE_SIZE),
        order=(1, 0),
    )
    weight_block_ptr = tl.make_block_ptr(
        weight_ptr,
        shape=(D,),
        strides=(weight_stride_dim,),
        offsets=(0,),
        block_shape=(D_TILE_SIZE,),
        order=(0,),
    )
    output_block_ptr = tl.make_block_ptr(
        output_ptr,
        shape=(NUM_ROWS,),
        strides=(output_stride_row,),
        offsets=(row_tile_idx * ROWS_TILE_SIZE,),
        block_shape=(ROWS_TILE_SIZE,),
        order=(0,),
    )
    
    # 初始化用于写入结果的缓冲。
    output = tl.zeros((ROWS_TILE_SIZE,), dtype=tl.float32)
    for i in range(tl.cdiv(D, D_TILE_SIZE)):
        # 加载当前 block pointer 指向的数据。
        # ROWS_TILE_SIZE 可能不能整除 NUM_ROWS，D_TILE_SIZE 可能不能整除 D，
        # 因此两个维度都需要边界检查。
        row = tl.load(x_block_ptr, boundary_check=(0, 1), padding_option="zero")
        # row: (ROWS_TILE_SIZE, D_TILE_SIZE)
        weight = tl.load(weight_block_ptr, boundary_check=(0,), padding_option="zero")
        # weight: (D_TILE_SIZE,)
    
        # 计算行的加权和。
        output += tl.sum(row * weight[None, :], axis=1)
    
        # 指针移到下一块；参数是（行，列）的坐标增量。
        x_block_ptr = x_block_ptr.advance((0, D_TILE_SIZE))
        weight_block_ptr = weight_block_ptr.advance((D_TILE_SIZE,))
    
    # 将输出写入 output block pointer，每行一个标量。
    # ROWS_TILE_SIZE 可能不能整除 NUM_ROWS，因此需要边界检查。
    tl.store(output_block_ptr, output, boundary_check=(0,))
现在将内核包装成一个 PyTorch Autograd 函数，使其能够与 PyTorch 配合：接收 Tensor，返回 Tensor，后续还能在反向中配合 autograd 引擎。

class WeightedSumFunc(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, weight):
        # 缓存 x 与 weight，供反向使用。
        # 反向只收到相对于输出的梯度，
        # 需要据此计算相对于 x 与 weight 的梯度。
        D, output_dims = x.shape[-1], x.shape[:-1]
        # 把输入重塑为二维。
        input_shape = x.shape
        x = rearrange(x, "... d -> (...) d")
        ctx.save_for_backward(x, weight)

        assert len(weight.shape) == 1 and weight.shape[0] == D, "Dimension mismatch"
        assert x.is_cuda and weight.is_cuda, "Expected CUDA tensors"
        assert x.is_contiguous(), "Our pointer arithmetic will assume contiguous x"
        # 沿 embedding 维度大约循环 16 次。
        ctx.D_TILE_SIZE = triton.next_power_of_2(D) // 16
        ctx.ROWS_TILE_SIZE = 16  # 每个线程一次处理 16 个 batch 元素。
        ctx.input_shape = input_shape
        # 分配 empty 结果张量，注意元素不一定为 0。
        y = torch.empty(output_dims, device=x.device)
        # 在一维 grid 中启动 n 个 instance。
        n_rows = y.numel()
        weighted_sum_fwd[(triton.cdiv(n_rows, ctx.ROWS_TILE_SIZE),)](
            x, weight,
            y,
            x.stride(0), x.stride(1),
            weight.stride(0),
            y.stride(0),
            NUM_ROWS=n_rows, D=D,
            ROWS_TILE_SIZE=ctx.ROWS_TILE_SIZE, D_TILE_SIZE=ctx.D_TILE_SIZE,
        )
        return y.view(input_shape[:-1])
注意，使用 weighted_sum_fwd[(triton.cdiv(n_rows, ctx.ROWS_TILE_SIZE),)] 调用 Triton 内核时，我们通过传入元组 (triton.cdiv(n_rows, ctx.ROWS_TILE_SIZE),) 定义了 thread block 的“launch grid”。然后在内核中通过 tl.program_id(0) 访问 thread block 索引。

反向传播

由于定义了自己的内核，我们还需要编写自己的反向函数。

前向时，给定层的输入，需要计算输出。反向时，给定目标相对于输出的梯度，需要计算目标相对于每个输入的梯度。在这里，输入是一个 n×h 的矩阵 x 和长度 h 的权重向量 w。为简洁起见，把运算记为 f(x,w)，输出属于 n 维空间。假设已知损失相对于该层输出的梯度，使用多元链式法则可得：

$$ (\nabla_x\mathcal L){ij} =\sum{k=1}^{n} \frac{\partial f(x,w)k}{\partial x{ij}} (\nabla_{f(x,w)}\mathcal L)k =w_j(\nabla{f(x,w)}\mathcal L)_i. \tag{2} $$

$$ (\nabla_w\mathcal L)j =\sum{i=1}^{n} \frac{\partial f(x,w)i}{\partial w_j} (\nabla{f(x,w)}\mathcal L)i =\sum{i=1}^{n}x_{ij}(\nabla_{f(x,w)}\mathcal L)_i. \tag{3} $$

这给出了简单的反向公式。对于 x，应用式 (2)，取 w 与输出梯度的外积。对于 w，需要将传入的梯度与对应行相乘。

反向内核首先定义所有 block pointer，然后计算相对于 x 的梯度：

@triton.jit
def weighted_sum_backward(
    x_ptr, weight_ptr,                    # 输入
    grad_output_ptr,                      # 输入的梯度
    grad_x_ptr, partial_grad_weight_ptr,   # 输出的梯度
    stride_xr, stride_xd,
    stride_wd,
    stride_gr,
    stride_gxr, stride_gxd,
    stride_gwb, stride_gwd,
    NUM_ROWS, D,
    ROWS_TILE_SIZE: tl.constexpr, D_TILE_SIZE: tl.constexpr,
):
    row_tile_idx = tl.program_id(0)
    n_row_tiles = tl.num_programs(0)

    # 输入
    grad_output_block_ptr = tl.make_block_ptr(
        grad_output_ptr,
        shape=(NUM_ROWS,), strides=(stride_gr,),
        offsets=(row_tile_idx * ROWS_TILE_SIZE,),
        block_shape=(ROWS_TILE_SIZE,),
        order=(0,),
    )
    x_block_ptr = tl.make_block_ptr(
        x_ptr,
        shape=(NUM_ROWS, D,), strides=(stride_xr, stride_xd),
        offsets=(row_tile_idx * ROWS_TILE_SIZE, 0),
        block_shape=(ROWS_TILE_SIZE, D_TILE_SIZE),
        order=(1, 0),
    )
    weight_block_ptr = tl.make_block_ptr(
        weight_ptr,
        shape=(D,), strides=(stride_wd,),
        offsets=(0,), block_shape=(D_TILE_SIZE,),
        order=(0,),
    )
    grad_x_block_ptr = tl.make_block_ptr(
        grad_x_ptr,
        shape=(NUM_ROWS, D,), strides=(stride_gxr, stride_gxd),
        offsets=(row_tile_idx * ROWS_TILE_SIZE, 0),
        block_shape=(ROWS_TILE_SIZE, D_TILE_SIZE),
        order=(1, 0),
    )
    partial_grad_weight_block_ptr = tl.make_block_ptr(
        partial_grad_weight_ptr,
        shape=(n_row_tiles, D,), strides=(stride_gwb, stride_gwd),
        offsets=(row_tile_idx, 0),
        block_shape=(1, D_TILE_SIZE),
        order=(1, 0),
    )
    
    for i in range(tl.cdiv(D, D_TILE_SIZE)):
        grad_output = tl.load(
            grad_output_block_ptr, boundary_check=(0,), padding_option="zero"
        )  # (ROWS_TILE_SIZE,)
        # 用外积计算 grad_x。
        weight = tl.load(
            weight_block_ptr, boundary_check=(0,), padding_option="zero"
        )  # (D_TILE_SIZE,)
        grad_x_row = grad_output[:, None] * weight[None, :]
        tl.store(grad_x_block_ptr, grad_x_row, boundary_check=(0, 1))
    
        # 尽可能在当前块内归约各行，得到 grad_weight 的局部结果。
        row = tl.load(
            x_block_ptr, boundary_check=(0, 1), padding_option="zero"
        )  # (ROWS_TILE_SIZE, D_TILE_SIZE)
        grad_weight_row = tl.sum(row * grad_output[:, None], axis=0, keep_dims=True)
        tl.store(partial_grad_weight_block_ptr, grad_weight_row, boundary_check=(1,))
        # 第 0 维不会越界。
    
        # 沿 D 移到下一块。
        x_block_ptr = x_block_ptr.advance((0, D_TILE_SIZE))
        weight_block_ptr = weight_block_ptr.advance((D_TILE_SIZE,))
        partial_grad_weight_block_ptr = partial_grad_weight_block_ptr.advance((0, D_TILE_SIZE))
        grad_x_block_ptr = grad_x_block_ptr.advance((0, D_TILE_SIZE))
计算 x 的梯度很简单，将结果写入输出张量对应的 tile 即可。不过，计算 w 的梯度更有挑战。每个内核 instance 只负责 x 的一个行 tile，但现在需要跨 x 的所有行求和。

我们不在反向内核里直接完成全局求和，而是假设 partial_grad_weight_ptr 指向一个 n_row_tiles × H 的矩阵，其中第一维的局部结果只在 x 的单个行 tile 内完成归约。将结果写入该张量前，先在当前行 tile 内求和；内核外再用 torch.sum 汇总所有行 tile 的结果，得到 w 的梯度。[^1]

class WeightedSumFunc(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, weight):
        # ...（前面已经定义）

    @staticmethod
    def backward(ctx, grad_out):
        x, weight = ctx.saved_tensors
        ROWS_TILE_SIZE, D_TILE_SIZE = ctx.ROWS_TILE_SIZE, ctx.D_TILE_SIZE
        # 它们不一定要与前向相同。
        n_rows, D = x.shape
        # 每个 thread block 先写入局部缓冲，
        # 然后归约这个缓冲，得到最终梯度。
        partial_grad_weight = torch.empty(
            (triton.cdiv(n_rows, ROWS_TILE_SIZE), D), device=x.device, dtype=x.dtype
        )
        grad_x = torch.empty_like(x)
        weighted_sum_backward[(triton.cdiv(n_rows, ROWS_TILE_SIZE),)](
            x, weight,
            grad_out,
            grad_x, partial_grad_weight,
            x.stride(0), x.stride(1),
            weight.stride(0),
            grad_out.stride(0),
            grad_x.stride(0), grad_x.stride(1),
            partial_grad_weight.stride(0), partial_grad_weight.stride(1),
            NUM_ROWS=n_rows, D=D,
            ROWS_TILE_SIZE=ROWS_TILE_SIZE, D_TILE_SIZE=D_TILE_SIZE,
        )
        grad_weight = partial_grad_weight.sum(axis=0)
        return grad_x, grad_weight
最后，我们得到一个行为类似 torch.nn.functional 中函数的接口：

f_weightedsum = WeightedSumFunc.apply

FlashAttention-2 前向传播
原文 §4.2.2，p22–27。

你将根据 FlashAttention-2［Dao，2023］，用性能显著改善的 Triton 实现替换 PyTorch attention。FlashAttention-2 使用若干技巧按 tile 计算前向，从而获得高效的内存访问方式，并避免在全局内存中物化完整 attention 矩阵。

在进入这一节前，我们强烈建议至少阅读最初的 FlashAttention 论文［Dao 等，2022］，它会帮助你理解其高效 attention 的核心技术：跨 tile 在线计算 softmax。这一技术由 Milakov 等［2018］提出。也建议阅读参考文献 [4]，进一步理解 GPU 实际如何执行 PyTorch 代码。

理解普通 attention 的低效之处

回忆 attention 前向，暂时忽略 mask：

$$ S=QK^\top/\sqrt d. \tag{4} $$

$$ P_{ij}=\operatorname{softmax}j(S){ij}. \tag{5} $$

$$ O=PV. \tag{6} $$

标准反向为：

$$ dV=P^\top dO. \tag{7} $$

$$ dP=dOV^\top. \tag{8} $$

$$ dS_i=\operatorname{dsoftmax}(dP_i) =\left(\operatorname{diag}(P_i)-P_iP_i^\top\right)dP_i. \tag{9} $$

$$ dQ=dSK/\sqrt d. \tag{10} $$

$$ dK=dS^\top Q/\sqrt d. \tag{11} $$

可见，反向依赖前向中一些非常大的激活。例如，式 (7) 的 dV 计算需要 P，其形状为 (batch_size,n_heads,seq_len,seq_len)。这个激活矩阵的大小与序列长度的平方有关，这解释了前面测试长序列 attention 时遇到的显存问题。

在普通 attention 的前向和反向中，我们都要付出大量内存 IO，将 P 和其他大激活在片上 SRAM 与 GPU HBM 之间传输。标准实现会进行多次这样的传输，例如标准反向在式 (7) 与式 (9) 中都需要从 HBM 读取 P。

FlashAttention 的主要目标是避免对 attention 矩阵进行 HBM 读写，从而降低 IO 与峰值显存成本。我们通过三种技术实现：分块、重计算和算子融合。

分块

为了避免在 HBM 中读写 attention 矩阵，我们在不能访问整个输入的情况下计算 softmax 归约。具体来说，重构 attention 计算，把输入切成 tile，并多次遍历输入 tile，逐步完成 softmax 归约。

重计算

我们不在 HBM 保存形状为 (batch_size,n_heads,seq_len,seq_len) 的巨大 attention 中间矩阵，而是在 HBM 保存某些“激活检查点”，在反向中重新计算一部分前向，从而得到梯度计算需要的其他激活。FlashAttention-2 还保存 attention scores 的 logsumexp，记为 L，用于简化反向：

$$ L_i=\log\left(\sum_j\exp(S_{ij})\right). \tag{12} $$

在最终内核中，我们会在线计算这个值，但最终结果应该相同。将分块与重计算结合，内存 IO 与峰值使用量不再依赖 sequence_length 的平方，因此可以使用更长的序列。

译注（非原文）：上一句是原文表述。严格分析时，应区分“避免完整平方矩阵的全局存储”与“总 HBM IO 为线性”：固定片上容量下，不同 query tile 仍可能重复读取 K/V，不能据此认为全部 IO 一定关于长度线性增长。

算子融合

最后，把所有运算放进单个内核，可以避免对 attention 矩阵和其他中间激活反复进行内存 IO，这称为算子融合或内核融合。我们将编写单个 Triton 前向内核，在 HBM 与 SRAM 之间只进行有限数据传输，完成 attention 的全部运算。重计算在一定程度上使这种融合成为可能，因为它避免了通常为了将每个中间激活保存到 HBM 所付出的 IO。

要进一步理解这些技术，可以阅读 FlashAttention 相关论文［Dao 等，2022；Dao，2023］。

使用重计算的反向传播

借助 L，可以进行恰当的重算并高效完成反向。开始反向之前，先在全局内存中预计算：

$$ D=\operatorname{rowsum}(O\circ dO), $$

其中圆圈表示逐元素乘法。它等于：

$$ \operatorname{rowsum}(P\circ dP), $$

因为：

$$ P(dP)^\top=P(dOV^\top)^\top=(PV)dO^\top=OdO^\top, $$

并且对任意相同形状的矩阵 A、B：

$$ \operatorname{rowsum}(A\circ B)=\operatorname{diag}(AB^\top). $$

有了 L 和 D，就可以不调用 softmax 来完成反向。完整计算现在是：

$$ S=QK^\top/\sqrt d. \tag{13} $$

$$ P_{ij}=\exp(S_{ij}-L_i). \tag{14} $$

$$ dV=P^\top dO. \tag{15} $$

$$ dP=dOV^\top. \tag{16} $$

$$ dS_{ij}=P_{ij}(dP_{ij}-D_i). \tag{17} $$

$$ dQ=dSK/\sqrt d. \tag{18} $$

$$ dK=dS^\top Q/\sqrt d. \tag{19} $$

可以看到，这一系列操作不要求在前向时把 attention scores P 保存在 HBM；我们在式 (13)、(14) 中用 Q、K 与 L 重新计算它。

FlashAttention 前向细节

现在已经从整体上了解 FlashAttention-2 的技术，接下来深入你将实现的 FA2 前向内核细节。为了避免 attention 矩阵的 HBM 读写，我们希望分块计算，也就是独立计算每个输出 tile。这要求能够分块计算 P，最好沿 query 和 key 两个维度都分块。

但是，对 S 应用 softmax 时，需要对完整的行归约才能获得分母，因此不能直接逐块计算 P。FlashAttention-2 用在线 softmax解决这一问题。下文用下标 i 表示当前 query tile，用上标 (j) 表示当前 key tile。query 方向的 tile 大小为 Bq，key 方向为 Bk；不沿隐藏维度 d 分块。

我们还维护逐行的运行状态：

$$ m_i^{(j)},l_i^{(j)}\in\mathbb R^{B_q}. $$

m 是逐行的运行最大值，用来以数值稳定的方式计算 softmax，回忆作业 1 的相同技巧。每当 j 增大、读取新的 S 行片段时，更新 m。使用这个最大值计算未归一化 softmax 值，也就是分子：

$$ \widetilde P_i^{(j)} =\exp\left(S_i^{(j)}-m_i^{(j)}\right). $$

l 是 softmax 分母的运行表示，通过未归一化值更新：

$$ l_i^{(j)} =\exp\left(m_i^{(j-1)}-m_i^{(j)}\right)l_i^{(j-1)} +\operatorname{rowsum}\left(\widetilde P_i^{(j)}\right). $$

最终写出输出时，使用处理全部 key tile 后的最终分母完成归一化：

$$ l_i^{(T_k)}. $$

算法 1 展示 GPU 上的前向传播。

算法 1：FlashAttention-2 前向传播（原文 p25，逐项译写）

输入要求：

$$ Q\in\mathbb R^{N_q\times d},\quad K,V\in\mathbb R^{N_k\times d}, \qquad\text{tile 大小为 }B_q,B_k. $$

将 Q 划为 Tq 个 tile，每块 Bq×d：

$$ T_q=\left\lceil N_q/B_q\right\rceil,\qquad Q_1,\ldots,Q_{T_q}. $$

将 K、V 各划为 Tk 个 tile，每块 Bk×d：

$$ T_k=\left\lceil N_k/B_k\right\rceil,\quad K^{(1)},\ldots,K^{(T_k)},\quad V^{(1)},\ldots,V^{(T_k)}. $$

对 i=1,…,Tq 循环。

从全局内存加载 Qi。

初始化：

$$ O_i^{(0)}=0\in\mathbb R^{B_q\times d},\quad l_i^{(0)}=0\in\mathbb R^{B_q},\quad m_i^{(0)}=-\infty\in\mathbb R^{B_q}. $$

对 j=1,…,Tk 循环。

从全局内存加载当前 K、V tile。

计算 softmax 前的分数 tile：

$$ S_i^{(j)}=Q_i(K^{(j)})^\top/\sqrt d \in\mathbb R^{B_q\times B_k}. $$

计算逐行最大值：

$$ m_i^{(j)}=\max\left(m_i^{(j-1)},\operatorname{rowmax}(S_i^{(j)})\right) \in\mathbb R^{B_q}. $$

计算未归一化概率：

$$ \widetilde P_i^{(j)}=\exp(S_i^{(j)}-m_i^{(j)}) \in\mathbb R^{B_q\times B_k}. $$

更新分母：

$$ l_i^{(j)}=\exp(m_i^{(j-1)}-m_i^{(j)})l_i^{(j-1)} +\operatorname{rowsum}(\widetilde P_i^{(j)})\in\mathbb R^{B_q}. $$

更新输出累积值：

$$ O_i^{(j)}= \operatorname{diag}\left(\exp(m_i^{(j-1)}-m_i^{(j)})\right)O_i^{(j-1)} +\widetilde P_i^{(j)}V^{(j)}. $$

结束 key tile 循环。

归一化输出：

$$ O_i=\operatorname{diag}(l_i^{(T_k)})^{-1}O_i^{(T_k)}. $$

计算 logsumexp：

$$ L_i=m_i^{(T_k)}+\log(l_i^{(T_k)}). $$

将 Oi 写回全局内存，作为 O 的第 i 个 tile。

将 Li 写回全局内存，作为 L 的第 i 个 tile。

结束 query tile 循环。

返回 O 与 logsumexp L。

算法 2：分块 FlashAttention-2 反向传播（逐项译写）

输入要求：

$$ Q,O,dO\in\mathbb R^{N_q\times d},\quad K,V\in\mathbb R^{N_k\times d},\quad L\in\mathbb R^{N_q}, \qquad\text{tile 大小为 }B_q,B_k. $$

计算：

$$ D=\operatorname{rowsum}(O\circ dO)\in\mathbb R^{N_q}. $$

将 Q、O、dO 各划为 Tq 个 tile，每块 Bq×d：

$$ T_q=\lceil N_q/B_q\rceil;\quad Q_1,\ldots,Q_{T_q},\ O_1,\ldots,O_{T_q},
dO_1,\ldots,dO_{T_q}. $$

将 K、V 各划为 Tk 个 tile，每块 Bk×d：

$$ T_k=\lceil N_k/B_k\rceil;\quad K^{(1)},\ldots,K^{(T_k)},
V^{(1)},\ldots,V^{(T_k)}. $$

将 L、D 各划为 Tq 个长度 Bq 的 tile：

$$ L_1,\ldots,L_{T_q},\qquad D_1,\ldots,D_{T_q}. $$

对 j=1,…,Tk 循环。

从全局内存加载当前 K、V tile。

初始化：

$$ dK_0^{(j)}=dV_0^{(j)}=0\in\mathbb R^{B_k\times d}. $$

对 i=1,…,Tq 循环。

从全局内存加载 Qi、dOi。

计算分数 tile：

$$ S_i^{(j)}=Q_i(K^{(j)})^\top/\sqrt d \in\mathbb R^{B_q\times B_k}. $$

计算概率：

$$ P_i^{(j)}=\exp(S_i^{(j)}-L_i)\in\mathbb R^{B_q\times B_k}. $$

更新 dV：

$$ dV_i^{(j)}=dV_{i-1}^{(j)}+(P_i^{(j)})^\top dO_i \in\mathbb R^{B_k\times d}. $$

计算：

$$ dP_i^{(j)}=dO_i(V^{(j)})^\top\in\mathbb R^{B_q\times B_k}. $$

计算：

$$ dS_i^{(j)}=P_i^{(j)}\circ(dP_i^{(j)}-D_i) \in\mathbb R^{B_q\times B_k}. $$

更新 dK：

$$ dK_i^{(j)}=dK_{i-1}^{(j)}+(dS_i^{(j)})^\top Q_i/\sqrt d \in\mathbb R^{B_k\times d}. $$

结束 query 循环。

将最终 dK、dV 写回全局内存，作为第 j 个 tile：

$$ dK_{T_q}^{(j)},\qquad dV_{T_q}^{(j)}. $$

结束 key 循环。

对 i=1,…,Tq 循环。

从全局内存加载 Qi、dOi。

初始化：

$$ dQ_i^{(0)}=0\in\mathbb R^{B_q\times d}. $$

对 j=1,…,Tk 循环。

从全局内存加载当前 K、V tile。

计算分数 tile：

$$ S_i^{(j)}=Q_i(K^{(j)})^\top/\sqrt d \in\mathbb R^{B_q\times B_k}. $$

计算概率：

$$ P_i^{(j)}=\exp(S_i^{(j)}-L_i)\in\mathbb R^{B_q\times B_k}. $$

计算：

$$ dP_i^{(j)}=dO_i(V^{(j)})^\top\in\mathbb R^{B_q\times B_k}. $$

计算：

$$ dS_i^{(j)}=P_i^{(j)}\circ(dP_i^{(j)}-D_i) \in\mathbb R^{B_q\times B_k}. $$

更新 dQ：

$$ dQ_i^{(j)}=dQ_i^{(j-1)}+dS_i^{(j)}K^{(j)}/\sqrt d \in\mathbb R^{B_q\times d}. $$

结束 key 循环。

将最终 dQ 写回全局内存，作为第 i 个 tile：

$$ dQ_i^{(T_k)}. $$

结束 query 循环。

返回 dQ、dK、dV。

PyTorch 中的单节点分布式通信
原文 §5.1，p30–32。

先看一个简单的 PyTorch 分布式应用：生成四个随机整数张量，并计算它们的和。

在下面的分布式场景中，我们启动四个 worker 进程，每个进程生成一个随机整数张量。为了跨进程求和，调用 all-reduce 集合通信操作；它会用全局归约后的结果，即总和，替换各进程的原始数据张量。

先看代码：

import os
import torch
import torch.distributed as dist
import torch.multiprocessing as mp

def setup(rank, world_size):
    os.environ["MASTER_ADDR"] = "localhost"
    os.environ["MASTER_PORT"] = "29500"
    dist.init_process_group("gloo", rank=rank, world_size=world_size)

def distributed_demo(rank, world_size):
    setup(rank, world_size)
    data = torch.randint(0, 10, (3,))
    print(f"rank {rank} data (before all-reduce): {data}")
    dist.all_reduce(data, async_op=False)
    print(f"rank {rank} data (after all-reduce): {data}")

if __name__ == "__main__":
    world_size = 4
    mp.spawn(fn=distributed_demo, args=(world_size,), nprocs=world_size, join=True)

更仔细地看上面的脚本。mp.spawn 创建 nprocs 个进程，使用给定 args 执行 fn。调用形式为 fn(rank,*args)，rank 是 worker 的索引，范围从 0 到 nprocs−1。因此 distributed_demo 必须把整数 rank 作为第一个位置参数。此外，我们传入 world_size，它表示 worker 进程总数。

每个 worker 属于一个通过 dist.init_process_group 初始化的 process group。进程组表示一组通过共享 master 协调和通信的 worker。master 由 IP 和端口定义，运行 rank 0 进程。all-reduce 等集合通信操作作用于组内每个进程。

此处用 "gloo" 后端初始化，也可以选择其他后端。特别是，"nccl" 使用 NVIDIA NCCL 集合通信库，通常对 CUDA 张量性能更好。不过 NCCL 只能在有 GPU 的机器上使用，而 Gloo 可以在纯 CPU 机器上运行。分布式 GPU 训练应始终使用 NCCL；只有没有 GPU 的本地开发才使用 Gloo。本例使用 Gloo，是为了可以在纯 CPU 机器上本地执行和开发。

多 GPU 作业中，要确保不同 rank 使用不同 GPU。一种方式是在 setup 中调用 torch.cuda.set_device(rank)，这样 tensor.to("cuda") 会自动移动到指定设备。也可以为每个 rank 显式创建设备字符串，例如 device = f"cuda:{rank}"，然后将它用作数据移动的目标，例如 tensor.to(f"cuda:{rank}")。

分布式数据并行训练的朴素实现
原文 §5.2，p33。

了解了如何用 PyTorch 编写分布式应用后，现在构建一个最小的分布式数据并行训练实现，即 DDP。

数据并行把 batch 划到多个设备，例如 GPU，使我们可以训练单设备放不下的大 batch。例如四台设备每台最多处理 batch 32，数据并行便可以实现有效 batch 128。

朴素 DDP 的流程如下。首先，每台设备建立随机初始化的模型，使用 broadcast 将 rank 0 的模型参数发送给其他 rank。训练开始时，每台设备持有完全相同的模型参数和优化器状态，例如 Adam 的累积梯度统计。

给定 n 个样本的 batch，对 batch 分片，每台设备得到互不重叠的 n/d 个样本，其中 d 为数据并行设备数。d 应整除 n，否则有些 rank 工作更多，整个步骤会被最慢的 rank 限制。
每台设备用本地参数，在自己的 n/d 个样本上做前向和反向，计算梯度。此时，各设备的梯度仅来自自己的样本。
使用 all-reduce 对设备间梯度取平均，使每台设备得到在全部 n 个样本上的平均梯度。
每台设备执行 optimizer step，更新本地参数。从优化器角度看，它只是在优化一个本地模型。因为所有设备的初始模型、优化器状态相同，而且每步使用相同平均梯度，所以它们的参数和状态保持同步。这样就完成了一次训练迭代，可以重复以上过程。

补充答案（非原文；理论）

各 rank 样本数相同、局部 loss 使用 mean 时，全局梯度是各 rank 梯度的平均：

$$ g=\frac1N\sum_{r=0}^{N-1}g_r. $$

全局初始状态与平均梯度一致，便能保持每步更新一致。需区分 all-reduce 的 sum 与训练所需 average，保持共享参数身份，并同步冻结参数的初始值。当前提供的是机制说明，未新增实现或运行测试。

改进最小 DDP 实现
原文 §5.3，p34。

§5.2 的最小实现存在两个关键限制：

每个参数张量都单独执行 all-reduce。每次通信都有开销，因此批量合并通信可能减少这些成本。
等待整个 backward 完成后才通信。但 backward 是逐步计算的，因此某个参数梯度一旦准备好，就可以立刻通信，不必等待其他参数。这样可以重叠梯度通信与 backward 计算，降低 DDP 开销。
本部分会依次解决这两个问题，并测量对训练速度的影响。

将计算与逐参数梯度通信重叠
原文 §5.3.2，p34–36。

批量通信可能减少大量小 all-reduce 的启动开销，但全部通信时间仍直接构成训练额外开销。解决办法是利用 backward 逐层计算梯度的特点：从 loss 一侧向输入一侧推进，某个参数梯度就绪时立即 all-reduce，从而重叠 backward 计算与梯度通信。

首先，实现并测试一个 DDP wrapper，在 backward 中每个参数梯度就绪时异步 all-reduce。以下提示可能有用。

Backward hooks。 如果想在参数梯度累加完成后自动调用某个函数，可以使用 register_post_accumulate_grad_hook。[^4]

[^4]: 原文脚注 4：更多信息及用例见 register_post_accumulate_grad_hook 文档。

异步通信。 PyTorch 所有 collective 都支持同步 async_op=False 和异步 async_op=True。同步调用会阻塞，直到操作排入 GPU 队列。这不表示 CUDA 操作已经完成，因为 CUDA 本身异步；不过，后续使用其输出的函数会按预期工作。[^5]

异步调用返回一个分布式请求 handle。函数返回时，操作不保证已经排入 GPU 队列，更不保证完成。可以在返回的 handle 上调用 handle.wait()，等待操作排入 GPU 队列，从而使其结果可以被后续操作使用。

[^5]: 原文脚注 5：较复杂场景中，如果使用多个 CUDA stream，可能需要显式跨 stream 同步，以确保输出可供后续操作使用。参见 CUDA streams 文档。

例如，下面两个例子分别用同步和异步调用，对列表中的每个张量 all-reduce：

tensors = [torch.rand(5) for _ in range(10)]

# 同步：阻塞到操作排入 GPU 队列。
for tensor in tensors:
    dist.all_reduce(tensor, async_op=False)

# 异步：每次调用立即返回，最后再等待结果。
handles = []
for tensor in tensors:
    handle = dist.all_reduce(tensor, async_op=True)
    handles.append(handle)

# ...
# 可以执行不依赖 all_reduce 结果的其他命令。
# ...

# 确保 all-reduce 已排队，
# 使依赖其输出的其他操作能够被排队执行。
for handle in handles:
    handle.wait()
handles.clear()

实现一个处理 DDP 的 Python 类。它应包装任意 PyTorch nn.Module，在训练前广播权重，让各 rank 初始参数相同，并发起梯度平均的通信。推荐以下公开接口：

backward 较早产生的后部层梯度可以与前部层计算交叠；最后只暴露未被计算覆盖的通信尾部。关键是每个参数梯度累加完成再通信、各 rank collective 顺序一致、optimizer 消费梯度前建立正确依赖，并清理本步 handle。共享权重与梯度累积可能影响钩子触发语义，不能用“代码发了 async”代替实际 GPU overlap 证据。

优化器状态分片
原文 §6，p37–38。

DDP 概念简单，通常很有效，但每个 rank 都需要独立持有完整模型参数和优化器状态。这种冗余有显著显存成本。例如 AdamW 为每个参数保存两个浮点数，因此其状态占用模型权重两倍的内存。Rajbhandari 等 [5] 描述了通过跨 rank 划分优化器状态、梯度和参数，并在必要时通信来减少冗余的方法。

本部分实现一种简化的 optimizer state sharding，以减少每个 rank 的显存。每个 rank 的优化器不再管理全部参数，只管理约 1/world_size 的子集。每步只更新自己 shard 中的参数，然后广播更新后的参数给其他 rank，确保每次更新后模型仍同步。

全分片数据并行
原文 §7，p38–39。

使用 optimizer state sharding 与数据并行后，优化器状态与激活能够沿数据并行轴分配。但是，模型权重仍然重复：每张 GPU 上都有完整副本。

可以把数据并行轴变成全分片数据并行轴，即 FSDP，来解决这一问题。在 FSDP 中，每张 GPU 只保存每个权重张量的自己的那一片；为了执行前向或反向，需要通过 all-gather 从其他 GPU 获取其余片段，组成完整权重。

为了避免 GPU 计算等待通信，多数 FSDP 实现会在计算前预先调度该层 all-gather，使权重在需要时已经准备好，防止通信阻塞计算。这使权重分片的通信离开关键路径：只要通信跟得上计算且调度合理，就没有额外成本。

有些层的显存和计算很小，为它们通信的延迟不值得。应该标记这些层不进行 FSDP 分片。在我们的架构中，主要是 norm 层；剩下的是 embedding 和每个 linear。

虽然主权重需要存储为 FP32，因为任何重复累加的值都对精度敏感，但权重不必以 FP32 参与计算。混合精度中使用前总会转换为低精度计算类型，因此不妨在通信前就转换，以节约带宽。

分析并行策略
原文 §8，p39–40。

训练过程还可以沿更多维度并行化。常见策略包括：

数据并行 DP：将数据 batch 分到多个设备，每个设备计算自己 batch 的梯度，再跨设备平均梯度。
全分片数据并行 FSDP：在数据并行基础上，将优化器状态、梯度和权重也跨设备分片，以降低显存；前向和反向时，需要从其他设备收集权重 shard。
张量并行 TP：沿权重矩阵输入维或输出维分片。设备计算自己 shard 对应的激活，再跨设备归约或收集激活。
流水线并行 PP：按层把模型分为多个阶段，每个阶段在不同设备执行。
专家并行 EP：将混合专家模型中的专家分配到不同设备，每个设备计算自己的专家输出。
本节在简化设置下，通过基本数学计算选择并行策略，并决定如何组合它们。首先关注 DP、FSDP、TP 及其组合。我们会计算每种策略的通信成本，与计算成本比较，从而确定在通信成为瓶颈之前最多能扩展到多少设备。

关于 TPU/GPU 拓扑与并行策略的更详细讨论，TPU Scaling Book，即 Austin 等的参考文献 [6]，是很好的资料。更详细的流水线并行讨论见参考文献 [7] 的 The Ultra-Scale Playbook 附录。这两本资料其他部分也有很多可能有用的内容。

通信原语
原文 §8.1，p40–41。

第一步是理解通信原语。在简化设置中，假设有 N 个设备，编号 0,…,N−1，每对设备间有链路连接。假设每个设备的出口带宽为 W，即每个设备可以每秒 W 字节的速度向另一个设备发送数据。如何实现 gather 与 reduce？

实现 all-gather 的常见方式之一是 ring all-gather。回忆 all-gather：设备 i 最初有一个大小 S/N 的 chunk，最终得到大小为 S 字节的完整张量：

$$ x=[x_0,\ldots,x_{N-1}]. $$

在 ring all-gather 中，把设备排成一圈。每一步，每个设备把当前 chunk 发给右侧邻居，并保存从左侧收到的 chunk。重复这一过程，把刚收到的 chunk 继续向右传，同时从左收到新的 chunk。N−1 步之后，每个设备都有完整张量。

在理想设置下，每步各设备同时发送 S/N 的 chunk，出口带宽 W，共 N−1 步，因此耗时：

$$ T_{\mathrm{AG}}=\frac{N-1}{N}\frac{S}{W}. $$

接下来分析 ring reduce-scatter。在 reduce-scatter 中，每个设备 i 最初有一个大小 S 的完整张量：

$$ x^{(i)}. $$

我们希望计算：

$$ y=\sum_{i=0}^{N-1}x^{(i)}, $$

但最终每个设备 i 只持有大小 S/N 的一个 chunk，即 yi。与 ring all-gather 一样，先把设备排成环。每个设备将自己的输入划为 N 块：

$$ x^{(i)}=[x_0^{(i)},\ldots,x_{N-1}^{(i)}], \qquad\text{每块大小为 }S/N. $$

像 ring all-gather 一样传递这些 chunk，不过每个设备在继续传递之前，要把自己的贡献加到 chunk 的部分和中。具体来说，第 t=1,…,N−1 步，设备 i 执行：

如果 t=1，初始化部分和：

$$ y\leftarrow x^{(i)}. $$

向右侧设备发送：

$$ y_{(i-t)\bmod N} \longrightarrow \text{设备 }(i+1)\bmod N. $$

从左侧设备接收：

$$ z_{(i-t-1)\bmod N} \longleftarrow \text{设备 }(i-1)\bmod N. $$

更新本地部分和：

$$ y_{(i-t-1)\bmod N} \leftarrow y_{(i-t-1)\bmod N}+z_{(i-t-1)\bmod N}. $$

N−1 步后，设备 i 得到 chunk yi 的完整总和，因此 ring reduce-scatter 与 ring all-gather 一样，耗时：

$$ T_{\mathrm{RS}}=\frac{N-1}{N}\frac{S}{W}. $$

最后实现 ring all-reduce。每个设备 i 最初持有大小 S 的完整输入，最终都持有总和：

$$ y=\sum_{i=0}^{N-1}x^{(i)}. $$

我们先执行 ring reduce-scatter，再执行 ring all-gather，所以耗时：

$$ T_{\mathrm{AR}}=2\frac{N-1}{N}\frac{S}{W}. $$

题目：另一种 Ring All-Reduce（alternate_ring_all_reduce，1 分）

若 t=1，初始化部分和：

分析数据并行
原文 §8.2，p41–42。

有了通信原语，现在可以分析并行策略。我们研究单个 FFN 层的并行化。回忆输入 x 的前向：

$$ x_1=xW_1. \tag{20} $$

$$ x_2=xW_2. \tag{21} $$

$$ z=f(x_1)*x_2. \tag{22} $$

$$ y=zW_3. \tag{23} $$

其中：

$$ x:(B,D),\qquad W_1,W_2:(D,D_{\mathrm{FF}}),\qquad W_3:(D_{\mathrm{FF}},D). $$

f 是逐元素激活函数，例如 SiLU，星号表示逐元素乘法。

显式写出反向也很有用。给定 shape 为 (B,D) 的 dy，反向为：

$$ dz=dyW_3^\top. \tag{24} $$

$$ dx_2=dz*f(x_1). \tag{25} $$

$$ dx_1=dzf'(x_1)x_2. \tag{26} $$

$$ dx=dx_1W_1^\top+dx_2W_2^\top. \tag{27} $$

$$ dW_3=z^\top dy. \tag{28} $$

$$ dW_2=x^\top dx_2. \tag{29} $$

$$ dW_1=x^\top dx_1. \tag{30} $$

这里星号仍表示逐元素乘法。

在使用 N_DP 个设备的数据并行中，将 x 按 batch 切为：

$$ x^{(i)}:\left(B/N_{\mathrm{DP}},D\right). $$

前向如常进行，不需要 collective，产生：

$$ y^{(i)}:\left(B/N_{\mathrm{DP}},D\right). $$

反向对按 batch 分片的激活正常计算，设备 i 得到：

$$ dW_3^{(i)}=(z^{(i)})^\top dy^{(i)}. \tag{31} $$

$$ dW_2^{(i)}=(x^{(i)})^\top dx_2^{(i)}. \tag{32} $$

$$ dW_1^{(i)}=(x^{(i)})^\top dx_1^{(i)}. \tag{33} $$

这里不是对全部 B 个外积求和，而是只有自己输入 shard 上 B/N_DP 个外积的部分和。因此，需要跨设备 all-reduce，得到三个完整梯度。

分析全分片数据并行
原文 §8.3，p42–44。

接下来分析 FSDP。与 DP 一样，FSDP 对输入和激活的 batch 维分片；为了节省显存，还分片 optimizer 状态、梯度和权重。权重可以沿任意一维切分，在设备 i 上得到三个权重 shard，每个元素数为：

$$ \left|W_1^{(i)}\right| =\left|W_2^{(i)}\right| =\left|W_3^{(i)}\right| =\frac{DD_{\mathrm{FF}}}{N_{\mathrm{FSDP}}}. $$

前向仍然是在局部 batch 上执行数据并行前向。但首先必须跨设备 all-gather 权重：

$$ W_1=\operatorname{all\text{-}gather} \left({W_1^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{34} $$

$$ W_2=\operatorname{all\text{-}gather} \left({W_2^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{35} $$

$$ W_3=\operatorname{all\text{-}gather} \left({W_3^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{36} $$

$$ \text{执行按 batch 分片的前向传播。} \tag{37} $$

all-gather 的具体执行时间有一定自由度：只要在权重使用之前准备好，使用后丢弃以控制显存即可。为了简洁，这一节把三个 gather 一起列出。

与前向类似，反向先收集权重。然后做局部 batch 的反向，但不再需要 all-reduce，因为每台设备只需要自己 shard 的梯度。因此改为 reduce-scatter：

$$ W_1=\operatorname{all\text{-}gather} \left({W_1^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{38} $$

$$ W_2=\operatorname{all\text{-}gather} \left({W_2^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{39} $$

$$ W_3=\operatorname{all\text{-}gather} \left({W_3^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{40} $$

$$ \text{执行按 batch 分片的反向传播。} \tag{41} $$

$$ dW_1^{(i)}=\operatorname{reduce\text{-}scatter} \left({dW_1^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{42} $$

$$ dW_2^{(i)}=\operatorname{reduce\text{-}scatter} \left({dW_2^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{43} $$

$$ dW_3^{(i)}=\operatorname{reduce\text{-}scatter} \left({dW_3^{(i)}}{i=0}^{N{\mathrm{FSDP}}-1}\right). \tag{44} $$

注意分片上标 (i) 在这里有重载含义：reduce-scatter 的输入是完整权重形状上的部分和，输出是分片权重形状上的完整总和。

分析张量并行
原文 §8.4，p44–45。

实践中，FSDP 经常与张量并行 TP 结合。TP 沿权重矩阵的输入维或输出维跨设备分片。输入维分片常称为“row parallel”，输出维分片常称为“column parallel”。

具体来说，要分片矩阵乘 xW，设：

$$ x:(B,D),\qquad W:(D,D_{\mathrm{FF}}). $$

列并行的 shard 为：

$$ W^{(i)}:(D,D_{\mathrm{FF}}/N_{\mathrm{TP}}), $$

于是：

$$ xW=\operatorname{all\text{-}gather} \left({xW^{(i)}}{i=0}^{N{\mathrm{TP}}-1}\right). \tag{45} $$

行并行则有：

$$ W^{(i)}:(D/N_{\mathrm{TP}},D_{\mathrm{FF}}), $$

每台设备在矩阵乘前，将 x 截取为对应输入片：

$$ x^{(i)}:(B,D/N_{\mathrm{TP}}). $$

于是：

$$ xW=\operatorname{all\text{-}reduce} \left({x^{(i)}W^{(i)}}{i=0}^{N{\mathrm{TP}}-1}\right). \tag{46} $$

为了并行化 FFN，我们使用特定组合：W1 和 W2 列并行，即输出维分片，W3 行并行，即输入维分片。由于行并行权重只需要输入的一个切片，这种配置可以跳过列并行权重之后的 all-gather。对形状 (B,D) 的输入，前向为：

$$ x_1^{(i)}=xW_1^{(i)}. \tag{47} $$

$$ x_2^{(i)}=xW_2^{(i)}. \tag{48} $$

$$ z^{(i)}=f(x_1^{(i)})*x_2^{(i)}. \tag{49} $$

$$ y^{(i)}=z^{(i)}W_3^{(i)}. \tag{50} $$

$$ y=\operatorname{all\text{-}reduce} \left({y^{(i)}}{i=0}^{N{\mathrm{TP}}-1}\right). \tag{51} $$

其中 W1/W2 的 shape 为 (D,D_FF/N_TP)，W3 的 shape 为 (D_FF/N_TP,D)。

(a) 中间激活的特征维为 D_FF/N_TP。各设备使用相同 dy，对自己特征分支反向：

$$ dz^{(i)}=dy(W_3^{(i)})^\top, $$

$$ dx_2^{(i)}=dz^{(i)}f(x_1^{(i)}), \qquad dx_1^{(i)}=dz^{(i)}f'(x_1^{(i)})*x_2^{(i)}, $$

$$ dW_3^{(i)}=(z^{(i)})^\top dy,\qquad dW_2^{(i)}=x^\top dx_2^{(i)},\qquad dW_1^{(i)}=x^\top dx_1^{(i)}, $$

$$ dx_{\mathrm{partial}}^{(i)} =dx_1^{(i)}(W_1^{(i)})^\top +dx_2^{(i)}(W_2^{(i)})^\top, $$

$$ \boxed{dx=\operatorname{all\text{-}reduce}i(dx{\mathrm{partial}}^{(i)})}. $$

三个 dW 已具有各自 weight shard 的 shape，不需在 TP 轴归约成完整 dW；dx 的各特征分支贡献则需要求和。

(b) 前向三个、反向六个矩阵乘，分片减少中间特征维：

$$ \boxed{ \mathrm{FLOPs}{\mathrm{fwd}}=\frac{6BDD{\mathrm{FF}}}{N_{\mathrm{TP}}}, \qquad \mathrm{FLOPs}{\mathrm{bwd}}=\frac{12BDD{\mathrm{FF}}}{N_{\mathrm{TP}}} }. $$

(c) 前向 all-reduce y，反向 all-reduce dx，各为 B×D 的 FP16 张量：

$$ \boxed{ T_{\mathrm{fwd,comm}}=T_{\mathrm{bwd,comm}} =\frac{4(N_{\mathrm{TP}}-1)BD}{N_{\mathrm{TP}}W} }. $$

(d) 用各自 FLOPs/C 与通信比较：

$$ \boxed{N_{\mathrm{TP}}\le1+\frac{3D_{\mathrm{FF}}W}{C}} \quad\text{（反向）}, $$

$$ \boxed{N_{\mathrm{TP}}\le1+\frac{3D_{\mathrm{FF}}W}{2C}} \quad\text{（前向）}. $$

前向更严格，因为它的通信与反向相同、计算只有一半。实际分片仍受维度整除和小矩阵效率限制。

二维并行：FSDP 与 TP
原文 §8.5，p45–46。

终于可以组合并行策略了。本节研究如何最优组合 FSDP 与 TP。提示：前面应该已经发现，batch size 与模型尺寸限制了最多能扩展到多少设备；把它们增大，可以在不受通信限制的情况下继续增加设备。

遗憾的是，当 batch size 超过某一点时，性能会开始下降，因为梯度噪声明显减小，失去 SGD 的隐式正则化性质；这一点常称为“critical batch size”。而 scaling laws 常会告诉我们模型应该多大，这正是下一次作业要做的事。

本节考虑简化情景：有人给定所有问题参数，包括 batch size、模型尺寸、带宽、加速器速度。你的任务是选择 FSDP 与 TP 配置，在保持计算受限而非通信受限的同时，扩展到尽可能多的设备。

先介绍组合机制。每个设备有一个 TP rank i 和一个 FSDP rank j：

$$ i=0,\ldots,N_{\mathrm{TP}}-1,\qquad j=0,\ldots,N_{\mathrm{FSDP}}-1, $$

形成总设备数为以下乘积的二维 grid：

$$ N=N_{\mathrm{TP}}N_{\mathrm{FSDP}}. $$

先按 TP，把 W1/W2 沿输出维分片，W3 沿输入维分片。因此需要在激活上插入 TP 式 all-reduce。再按 FSDP，对输入 batch 维分片，并沿权重尚未被 TP 切分的另一个维度进一步分片。因此，在执行 TP 式前向/反向之前，需要 FSDP 式权重 all-gather；在 TP 式反向之后，需要对权重梯度 reduce-scatter。

结果是设备 (i,j) 持有：

$$ W_1^{(i,j)},W_2^{(i,j)} :\left(\frac D{N_{\mathrm{FSDP}}}, \frac{D_{\mathrm{FF}}}{N_{\mathrm{TP}}}\right), $$

$$ W_3^{(i,j)} :\left(\frac{D_{\mathrm{FF}}}{N_{\mathrm{TP}}}, \frac D{N_{\mathrm{FSDP}}}\right). $$

给定局部 batch 输入：

$$ x^{(j)}:\left(B/N_{\mathrm{FSDP}},D\right), $$

前向可写为：

$$ W_1^{(i)}=\operatorname{all\text{-}gather} \left({W_1^{(i,j)}}{j=0}^{N{\mathrm{FSDP}}-1}\right). \tag{52} $$

$$ W_2^{(i)}=\operatorname{all\text{-}gather} \left({W_2^{(i,j)}}{j=0}^{N{\mathrm{FSDP}}-1}\right). \tag{53} $$

$$ W_3^{(i)}=\operatorname{all\text{-}gather} \left({W_3^{(i,j)}}{j=0}^{N{\mathrm{FSDP}}-1}\right). \tag{54} $$

$$ x_1^{(i,j)}=x^{(j)}W_1^{(i)}. \tag{55} $$

$$ x_2^{(i,j)}=x^{(j)}W_2^{(i)}. \tag{56} $$

$$ z^{(i,j)}=f(x_1^{(i,j)})*x_2^{(i,j)}. \tag{57} $$

$$ y^{(i,j)}=z^{(i,j)}W_3^{(i)}. \tag{58} $$

$$ y^{(j)}=\operatorname{all\text{-}reduce} \left({y^{(i,j)}}{i=0}^{N{\mathrm{TP}}-1}\right). \tag{59} $$

最终得到按 batch 分片的输出：

$$ y^{(j)}:\left(B/N_{\mathrm{FSDP}},D\right). $$

为了简洁，本节省略反向，只关注前向。不过到这里，你应该已掌握自行写出反向所需的全部信息。

补充答案（非原文；理论）

为简洁，仅在答案中记：

$$ f=N_{\mathrm{FSDP}},\quad t=N_{\mathrm{TP}},\quad a=\frac{BW}{C},\quad b=\frac{3D_{\mathrm{FF}}W}{2C}. $$

(a) 每卡同时减少 batch 与特征维：

$$ \boxed{\mathrm{FLOPs}{\mathrm{fwd}}=\frac{6BDD{\mathrm{FF}}}{ft}}. $$

(b) FSDP 收集的是 TP 分片后的三个矩阵；TP 归约的是局部 batch 的输出：

$$ T_F=\frac{6(f-1)DD_{\mathrm{FF}}}{ftW}, \qquad T_T=\frac{4(t-1)BD}{ftW}, $$

$$ \boxed{T_{\mathrm{comm}}=\max(T_F,T_T)}. $$

(c) 两项分别不大于计算时间 6BDD_FF/(ftC)，得到 f−1≤a、t−1≤b，因此：

$$ \boxed{ N\le(1+a)(1+b) =\left(1+\frac{BW}{C}\right) \left(1+\frac{3D_{\mathrm{FF}}W}{2C}\right) }. $$

保留了 ring 的有限设备修正。实际整数配置还需要维度支持合法分片。

(d) 两轴不能重叠时，通信相加，条件为：

$$ \frac{f-1}{a}+\frac{t-1}{b}\le1. $$

最优点在等式边界。令：

$$ K=1+\frac1a+\frac1b, $$

则 f/a+t/b=K。内部最优在两个归一化分量相等时取得：

$$ f^\star=\frac{a+1+a/b}{2}, \qquad t^\star=\frac{b+1+b/a}{2}. $$

如果两者均至少为 1：

$$ \boxed{N_{\max}=\frac{(ab+a+b)^2}{4ab}}. $$

还需考虑某条轴退化为 1 的情况：

$$ \boxed{ N_{\max}= \begin{cases} 1+b, & a<\dfrac{b}{b+1},\[5pt] 1+a, & b<\dfrac{a}{a+1},\[5pt] \dfrac{(ab+a+b)^2}{4ab}, & \text{其余情况}. \end{cases} } $$

当 a、b 都很大时，可重叠的上限约为 ab，不能重叠时约为 ab/4，即：

$$ N_{\max,\mathrm{overlap}}\approx \frac{3BD_{\mathrm{FF}}W^2}{2C^2}, \qquad N_{\max,\mathrm{shared}}\approx \frac{3BD_{\mathrm{FF}}W^2}{8C^2}. $$

这反映两条轴分别约缩半，设备数乘积约变成四分之一。以上严格依据题目理想通信模型，实际吞吐还受延迟、拓扑和依赖调度限制。
