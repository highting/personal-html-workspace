# 四场景工作流

以原 `main` 的小红书实现为基础，四场景按用途分路。新流程不替换 `rednote_render.py` 或原主题；学习/博客/汇报使用新增静态模板。先读根技能和[场景规则](content-scenes.md)，从[Prompt入口](../prompts/README.md)读取当前保存的共同与场景规则。日常路线为“当前 Prompt 与原稿 → `output/_work/` 制作 → 验收 → `output/<成品名>/` 交付”；`archive/` 仅用于历史归档，不参与新任务准备、构建或交付。

## 准备材料

用户将新材料拖入 `inputs/待分类/` 后，在会话中发出制作要求；代理先归类到 `inputs/<内容分类>/<主题>/`，不改正文或破坏附件相对路径，再运行准备脚本。已有分类和 `blogs/` 原地兼容，制作时原稿只读。只有主题或调研结果时，按[工作区约定](workspace.md#输入与正文选择)保存可追溯的材料基线，准备后在 `work/` 自行拟稿并审核，不跳过正文直接排页面。分类、成品命名和版本按该约定执行。优先识别 `main.md`、`article.md`、`index.md`，已知正文显式传 `--entry`；其他格式用对应工具读取，转换稿放 `work/`。

```bash
python -X utf8 scripts/prepare_content.py "inputs/机器学习/Softmax" --scene learning --name Softmax-学习
```

`--entry` 指定相对主稿路径，`--mode html|images` 仅记录辅助图工具。新成品用 `<主题短名>-<场景>`，始终显式传 `--name`，并核对已有目标的来源、场景，防止入口互相覆盖。脚本建立 `output/_work/<成品名>/<时间戳>-<scene>-<mode>/` 的 `source/`、`work/`、`delivery/`，输出 `run.json`；从项目 `prompts/` 读取共同与场景原文，追加本次任务信息，保存为 `work/任务Prompt.txt` 规则快照。学习、博客、汇报另初始化空的 `work/content-review.json`，供代理在改稿与验收过程中记录实际依据，空文件不代表已经审读。新请求或已交付后的改版新建工作目录，同次修正复用。`source/` 是只读快照；其哈希用于交付核对。

读取 `prompts/common.txt`、所选 `prompts/scenes/<scene>.txt` 和[成品视觉规则](visual-system.md)，先按场景确定覆盖与解释深度，在 `work/` 写出完整场景稿。学习梳理主题内应掌握的核心、前提与直接相关知识；博客锁定具体知识点；汇报明确本次目的、听众应形成的判断及其依据。依共同 Prompt 先完成事实、覆盖和结构的内容修订，再仅凭成稿完成读者视角修订：学习能否跟随解释学懂，博客能否简明理解原理，汇报能否迅速抓住主判断及其依据。仍有实质问题就继续改稿，不从提纲直接制作 HTML。配图规划与修订同步，逐段主动找出有理解收益的位置，确定图面关系及正文分工，不因已有图数而省略。稿件同时达到共同与场景 Prompt 的退出条件后，才制作最终图解与代表性页面，实际查看后完成全篇；制作中暴露解释问题时回改正文。取舍与主要修订记在已有工作记录，不另建逐轮审批流程，也不把策划表、缺口说明或占位文案交给读者。

## 学习与博客

在 `work/` 写好的 Markdown 支持 YAML 的 `title`、`description`、`author`、`date`；后两者只采用真实信息。标题可从第一个一级标题获取。h2章节、h3小节形成目录；内嵌SVG与本地图片可作图解，公式行内用 `\( ... \)`，独立用 `$$ ... $$`。

```bash
python -X utf8 scripts/build_content.py "<work_entry>" --scene learning --output "<run_dir>/work/index.html"
python -X utf8 scripts/render_content.py "<run_dir>/work/index.html" --scene learning --output-dir "<artifact_dir>"
```

博客将两处scene改为 `blog`，与学习共用模板，但按具体知识点简明解释原理，不主动扩展；学习保留较广覆盖与详细、直白的解释，正文不能只靠更改scene互换。构建器可接收可信 `.html` 正文片段，直接放入 `.prose`。`--theme light|dark|system` 设置初始偏好，顶部配色选择器提供浅深各三套，太阳/月亮按钮切换并记住两种模式各自的选择；字号可调10–24px，图片和SVG支持点击/Enter放大、Esc关闭。放大视图保留原图注的条件、公式和链接，适合窗口同时按宽高计算；放大后可滚动或聚焦图像区用方向键查看，关闭恢复原位置与焦点。目录可收起。CSS/JS、KaTeX和数学字体内嵌，本地 `<img src>` 转为data URI；网络图片需先本地化。

顶部工具栏直接提供字体、字号、正文宽度滑条（页面宽度的40%–80%，默认60%）、恢复默认宽度、打印、配色和明暗切换，不再使用阅读设置弹窗。宽度显示并记忆百分比，随窗口变化保持相同比例，不设固定像素上限；旧像素偏好不套用到百分比。滑条拖动即时重排，整次拖动保持同一阅读锚点，支持键盘方向键；工具栏尺寸独立于正文宽度和目录状态，拖动中滑条轨道保持固定，数值按拖动方向连续变化。目录入口固定在页面左侧，工具栏收起后仍可用；正文加宽后侧栏放不下时，由按钮展开目录，正文临时让位并保持两栏之间的留白，关闭后恢复所选正文宽度；目录右边缘可左右拖动并记忆宽度。打印按钮可打开浏览器对话框保存 PDF。浏览器 `Ctrl+F` / `⌘+F` 负责文内查找，不另外实现搜索。打印使用白底，完整展开补充内容和代码，保留动画完整步骤，结束后恢复折叠状态。

字体下拉框支持按名称搜索，提供默认内嵌字体、系统界面字体及浏览器配置的无衬线/衬线/等宽类别；点击“加载本机字体”后由浏览器请求授权并返回候选，按字体家族去重，未支持或未授权时仍可使用基础选项。方向键选择、Enter应用、Esc关闭；选择会记住，本机字体缺字时回退默认字体。代码、公式和固定布局的SVG保持原字体。

调节字体、字号、正文宽度、收起桌面侧栏或开合顶部工具栏时保持当前可见的阅读内容；文字按插入点定位，图面和段间留白按当前块定位。工具栏右侧上箭头可隐藏整栏，右上角固定的下箭头可恢复；按钮常态只显示小图标，悬停说明和无障碍标签保留用途；记住手动选择，隐藏控件不进入Tab顺序，开合后焦点落在可见的对应按钮。自然换行仍可能让同一行末尾的词移到下一行，但不能因整篇重排而跳到相邻段落。缩小桌面视口或浏览器放大后，目录仍在当前视口中随正文停驻并可独立滚动；开合和拖动目录均保持阅读位置，不遮盖正文；选择章节后收起，Esc收起并将焦点返回目录按钮；收起工具栏同时关闭展开的目录。

代码围栏可写为 `` ```{.python title="example.py" data-highlight="2 4-6"} ``，分别指定语言、文件名和重点行；普通 `` ```python `` 同样可用。代码在构建时由Pygments高亮，阅读时不联网；复制保留完整代码，超过20行提供展开按钮。无法访问剪贴板时明确提示，不显示虚假成功。

长行超出代码容器时提供“换行”按钮，读者可在原始行布局和软换行之间切换；短行不增加按钮。续行对齐代码正文，原始行号只显示一次，重点行覆盖整个逻辑行。显示换行不修改源文本，复制仍保留原有空格与换行。

宽表格只在实际溢出时显示方向提示，随左右位置更新；可通过Tab聚焦后用左右方向键滚动。表格区域采用图注或所在章节命名，未溢出的表格不增加Tab停留点。窗口、字号及折叠内容变化后重新判断，不通过截断内容消除溢出。

补充内容用 `<details markdown="1">` 包裹，第一项写 `<summary>补充内容标题</summary>`，中间留空行后写Markdown，最后关闭 `</details>`。核心条件与关键结论留在展开的主线中，不为展示功能强行折叠。检查器会展开补充内容与长代码后检查，默认状态另保留首屏截图。

章节标题自动获得稳定定位链接，悬停或键盘聚焦时显示复制按钮。目录点击与章节链接直接定位目标并展开其所在补充内容，不使用跨章节的平滑滚动动画。阅读位置保存在当前浏览器中，再次打开由读者点击“继续阅读”；不会自动跳转。可在front matter指定稳定的 `document_id`，默认按场景与标题区分；同名不同文章应使用不同ID。浏览器禁用本地存储时仍可阅读，文件链接只用于本机定位。

点击“继续阅读”时先恢复已展开的补充内容、代码换行与长代码展开状态，再按章节及章内位置定位。代码显示状态按所在标题、语言、文件名和源文本识别；代码内容改变时不套用旧状态。普通打开或章节链接仍采用默认代码布局，显示状态不会自动改成上次的选择。

长文图片和SVG可拖动右下角手柄，在正文栏内等比例调整大小；方向键微调，Home/End到最小/最大，双击手柄或点击恢复按钮回到原大小。SVG以viewBox宽度作为CSS像素尺寸基准，超出正文栏时自适应收窄，避免百分比铺满抵消浏览器缩小；手动调整仍按默认图面尺寸的40%–100%记忆。图片及SVG在正文栏内居中，图注居中并随图面宽度调整，点击图片仍打开大图。独立Markdown图片后紧跟以“图1”等开头的斜体图注时，构建器将两者组合为figure；一般文字不自动当图注。原图保持原貌，自绘SVG使用主题变量。适合步骤演示时可按[视觉规则](visual-system.md#用动画解释变化)添加可控动画；默认完整静态图，打印/导出不截取随机中间态。

长文需要集中列出处时，可在工作稿写`<aside class="article-sources" aria-label="来源">`，内含`<p class="sources-title">来源</p>`及带链接的出处段落，最后关闭`</aside>`。它使用次要字号与正常字形，不加入正文目录；来源和图示说明由实际材料提供，模板不自动生成。关键论断的引用仍放在论断附近。

首次构建前显式执行 `python -X utf8 scripts/download_content_fonts.py`，下载并校验固定版本Noto Sans SC（思源黑体系列）缓存。构建器用FontTools/Brotli按实际字符制作WOFF2子集，中文正文、标题、SVG、代码中文和备注可离线显示；字体及OFL许可内嵌成品，完整缓存不入Git。来源见[字体说明](../assets/vendor/noto-sans-sc/README.md)。仍需核对实际中文字形与字体，而不只看CSS声明。

不引入React/Next/Astro后台；正文片段可按内容调整排版，模板不是固定图数或章节数的约束。来源链接允许联网跳转，但阅读不依赖联网。不要在成品追加制作记录或机器检查表。

## 技术汇报

按[汇报 Prompt](../prompts/scenes/report.txt)先明确成果、进展、方案评审或论文/技术分享的主目的与听众应形成的判断，再完成逐页场景稿：本页/页组主信息、证据或图面、必要条件、实际口头解释与衔接。代表页用来联合调整视觉构图与页内文字，一个任务可跨多页。结果、计划、教学构造、作者成果和自己的工作如实区分；观众页保留关键证据与条件，备注补充解释。文档缺口、制作提醒与检查记录只放 `work/` 或 `delivery.md`，不藏入备注。

Markdown围栏外的独立 `---` 作为分页符，代码和公式保持完整；每页标题用 `#` 或 `##`。`<!-- notes: 备注正文 -->` 只保存实际口头展开，不存放制作提醒或文档不足的解释。备注默认收起，按钮或N主动切换、Esc收起，导出PNG时隐藏；展开后在当前页面可见，不是独立讲者屏。复杂内容可写可信HTML片段，完整页面遵循以下结构：

有独立标题页时，可在整篇front matter设置`cover: true`，仅让第一页采用较大标题和居中的简短内容组；未设置时第一页继续使用正文布局。封面同样检查510px正文安全区，长内容应调整或拆页。可信HTML可用`class="slide slide-cover"`明确选择该样式，不为每页增加独立模板。

```html
<section class="slide" data-export-page data-notes="讲者备注">
  <p class="eyebrow">汇报主题</p>
  <div class="slide-body"><h2>本页主张</h2><p>证据与必要条件</p></div>
  <footer class="slide-footer"><span>主题或来源</span><span>01 / 04</span></footer>
</section>
```

同一HTML片段可包含多页；必须使用上述class和标记，正文在 `slide-body` 安全区内。按信息关系复用版式：`.columns` 为等宽双栏；`.report-split` 为左侧说明、右侧证据，说明标题32px且两栏顶边对齐；`.report-comparison` 按实际子项排列两到三组开放对照；`.report-timeline` 按实际步骤分栏，过多则拆页；单组内容使用完整内容区。表格中的 `.report-value` 显式右对齐数值，`.report-highlight` 只强调关键行或单元格；不自动猜测指标含义。数值来自真实材料或标注教学构造，图表的尺度和条件按[视觉规则](visual-system.md)核对。可复用源稿见[版式样例](../demos/content/README.md)。固定页放不下先删冗余，再按论证关系调整或增页。

```bash
python -X utf8 scripts/build_content.py "<work_entry>" --scene report --output "<run_dir>/work/index.html"
python -X utf8 scripts/render_content.py "<run_dir>/work/index.html" --scene report --output-dir "<artifact_dir>" --theme light
```

`render_content.py` 使用模板的 `setContentTheme` 和 `activateContentExport({index})`，验证主题切换、键盘翻页、备注和每页边界；不猜测其他演示框架接口。汇报沿用 Quarto 默认主题的封面、正文与字体比例，目录按钮位于左下；`M`开合目录，关闭按钮、遮罩或`Esc`收起并返回目录按钮，点选章节后直达该页。页码位于右上，底边细线随翻页更新；导出隐藏工具和进度线，页内页码保留。实际验收须逐页逐句审读全部正文、标题、副标题、图中标签、图注、表下注、页脚、小字和讲者备注，确认每项都属于本次实际汇报且有依据，并核对汇报重点、图表数据与跨页衔接。确认备注默认隐藏、主动开合有效、PNG不含备注；隐藏不等于可以省略内容审核。自定义HTML需保留模板约定。`--browser-executable` 可指定已有Chromium，默认复用Playwright共享缓存。

## 检查与汇总

检查器离线加载HTML，输出 `qa.json` 与 `checks/` 截图。学习/博客生成明暗首屏、全篇与分屏截图；汇报只生成浅色检查图和白底 `page-01.png` 等，不生成深色样张。`checks/content-text.json` 提取页面文字、SVG标签与讲者备注并标记HTML哈希，供代理核对完整文案；位图文字、公式含义与代码仍须结合原页审读，文本提取不能代替实际查看。长文检查10/12/24px字号、100/150/200% CSS布局缩放，另按实际浏览器条件验证原生缩放；不把CSS缩放或DPR记录为原生浏览器操作。学习/博客/汇报不单独验收手机适配。实际查看全部内容，测试目录、主题、字号、图像放大与备注；逐项处理 `warnings` 中的可疑制作文案，覆盖列表、表格、页脚和备注。关键词只提供线索，不自动删除内容，也不能覆盖所有说法；没有警告仍须全量审读，存在警告则必须在最终记录中逐项说明保留理由。QA不能证明内容或审美已通过。

已有完整桌面Chrome时，可运行 `check_chrome_zoom.py` 验证100/150/200%的原生页面缩放，传入 `--scene`、`--output-dir` 和 `--browser-executable`。脚本使用独立临时普通配置，通过Chrome外观设置的Page zoom控件操作，核对DPR、CSS视口和CSS zoom，输出 `qa-chrome-zoom.json` 与截图；不修改日常浏览器配置。Headless Shell不提供该设置界面。原生zoom下CSS视口与浏览器图面像素不同，截图直接捕获完整表面并分屏覆盖内容，不用CSS坐标裁图。键盘快捷键与其他浏览器需另行验证，记录必须写明实际方法。

在已有 `work/content-review.json` 逐步记录内容与读者审读，`delivery.md` 引用该记录并汇总来源、主要修订和真实检查，不重复抄录。内容稿的审读在排版前完成；生成HTML后再核对图文、全部文案与呈现，补齐最终记录。改稿采用代表性改前/改后；首次制作依据原材料、所选范围和代表性成稿，不制造前后对照。记录具体章节/页序与判断依据，不能只写“检查通过”或把待办当结果。

| 字段 | 实际应记录的依据 |
|---|---|
| `scope` | 用户目标、已有基础及内容与章节/页序对应。学习列重要知识和必要前提；博客限定当前问题；汇报写明主目的、听众及应形成的判断，不默认个人成果。 |
| `content_review` | 事实、来源、覆盖与结构的核对及实质修订。学习核对重要知识的解释位置；博客说明扩展取舍；汇报核对主线所需证据、成果归属和真实限制。 |
| `reader_review` | 仅凭成稿跟随代表性难点、例子或论证，记录具体位置、得到的解释与已修复断点。学习/博客另按重要解释任务复核图解分布：图解决什么、哪些空档补图、哪些保留文字及原因；不能只报图数或泛称已讲清。 |
| `visual_review` | 全部成品的实际查看范围与依据。长文重点核对可读性和图文衔接；汇报先看视觉焦点、证据构图和整组节奏，再核对全部文字含备注。按场景注明实际外观与缩放方法，不用无溢出代替视觉判断。 |
| `warning_decisions` | 对象，键是当前 `qa.json` 的完整警告，值是保留该文案的具体理由；没有警告时为 `{}`。真正的制作残留先改稿并重新检查，不能用理由豁免；合法教学引用等才说明为何保留。 |

四个文字字段由代理填写实际依据，用户不需要填写表单。保留来源与未验证事项；真实研究边界仍在正文准确表达，制作过程未执行的检查留在记录。算法动画逐步对照代码核对输入、条件、操作、前后状态和结果，实际查看关键分支与更新，并验证回退与重置；流程框淡入或仅检查按钮、步号变化不算通过。

配色检查运行 `check_content_palettes.py <artifact_dir>/index.html --scene <scene> --output-dir <artifact_dir>/checks/palettes`。学习/博客检查六套配色，汇报只检查纯白与纸白；逐套核对语义文字对比度、桌面三档窗口的控件与内容边界，并保存代表画面。长文另保存外置阅读工具栏、打印样式和动画步骤。原生缩放使用上述独立检查，学习/博客覆盖明暗，汇报仅浅色；不能将窗口检查记作原生缩放检查。实际查看后交付，不额外生成汇报深色或小红书明暗样张。

```bash
python -X utf8 scripts/content_review.py "<run_dir>" --review "<run_dir>/work/content-review.json"
# 全部实际审读与检查完成后，将 run.json 的 status 标记为 completed
python -X utf8 scripts/publish_content.py "<run_dir>"
```

学习/博客/汇报要求本场景QA通过，并具备 `content_review.py` 生成的 `<run_dir>/content-review.json`；它绑定当前HTML、场景与原始快照，记录四项审读依据及当前文案警告的处理。缺少记录、字段为空、版本过期或警告未处理时，发布器拒绝更新入口。`completed` 和页面QA不能代替该记录；脚本只验证记录完整性及版本，不自动判断内容是否学得懂、论证是否正确。HTML/PNG修改后重新检查，HTML变化还须重新审读并生成记录，不能手改哈希或通过结果。旧工作目录再次交付也要补做当前版本的审读；已有短路径成品不会自动改写。短路径更新到 `output/<成品名>/`，旧交付保留在本次工作目录；失败时不替换已有成品。代理随后同步 `output/index.html` 中对应的内容分类、主题和场景条目并核对链接，发布脚本不会自动更新总览。回复优先链接成品 `index.html`。

## 小红书原流程

`inputs/` 与已有 `blogs/` 的日常新建工作目录统一用 `prepare_content.py --scene rednote` 准备，保存共同与场景Prompt，再由 `rednote_render.py` 制图。用 `--save-html` 保存源页；混入独立辅助图片时按[小红书验收](rednote-scene.md#检查与交付)填写最终页清单。运行 `python -X utf8 scripts/check_rednote.py <artifact_dir>`，检查连续页序、PNG解码与尺寸、HTML资源、公式及标签实际大小，生成390px宽预览。逐张查看原图和预览、完成内容审核后才标记 `completed`，再用 `publish_content.py` 汇总。发布器要求当前版本 `qa-rednote.json` 通过，核对图片、源页、资源及清单的哈希；改变后必须重新检查，缺少或过期QA不能发布。`prepare_blog.py` 与 `publish_blog.py` 兼容历史调用和工作目录，但同样执行此门槛；历史成品不自动改写，再次交付需在新工作目录重新验收。小红书不使用长文模板，检查记录不能替代目视验收。

这里的“发布”只指本地成品汇总。脚本不调用AI或生图、不上传社交平台；插件安装与GitHub上传是独立操作。
