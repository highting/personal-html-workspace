# 四种场景的策划与验收

## 个人学习 learning

按[学习 Prompt](../prompts/scenes/learning.txt)覆盖主题内的核心、必要前提与直接相关知识，按概念依赖组织连续长文，默认比同主题博客讲得更广、更细。用直白语言、贯穿例子和必要推导讲清对象、操作、原因与条件；涉及张量时说明关键形状变化及作用，不逐句翻译代码。不能自行收窄为少数论点，或用延伸阅读代替相关知识的实质解释；也不递归补齐整个学科。验收看读者能否不返回原稿就解释核心关系、跟随过程并完成简单应用或变化判断，不能只复述术语与结论。

HTML 使用可收起的左侧分层目录、舒适阅读宽度和清楚的章节间距。检查首屏、章节交界、主要图解、公式、代码和结尾，验证目录定位/收起、阅读进度与图标主题切换。默认交连续HTML，检查截图不是正文长图。

## 技术博客 blog

按[博客 Prompt](../prompts/scenes/blog.txt)围绕具体知识点简明讲清原理，开篇交代问题与核心判断，用必要解释、图解、例子或证据接通关键关系。只就近补足必需前提，不主动扩展为知识综述、变体大全或学习教程；必要理由与条件仍保留。标题直接表达主题，不制造悬念。保留连续段落；来源靠近所支持的论断，真实证据和教学构造分开。作者、日期、经历只写实际给出的信息。

HTML与学习共用阅读模板；解释深度与覆盖范围按博客目标取舍，不把学习稿直接删短。检查每段、每图是否直接帮助理解本文原理，以及导语、连续阅读节奏、图文衔接、来源、两种主题和结尾；不另设独立版式，不强制小红书的标题/配文文件。

## 技术汇报 report

按[汇报 Prompt](../prompts/scenes/report.txt)让听众快速理解本次成果、依据与意义，尽早给出重点，再组织必要背景与证据；方案、阶段进展、计划和已验证结果如实区分。一个讲解任务可跨多页，整组页面形成连贯论证。主要视觉焦点可以是图表、机制图或一段明确结论，不强制每页配图。所有文案都应是实际会向听众表达的内容，包括图注、表下注、页脚和小字；文档缺口、制作提醒与会前待办只留工作记录，也不放进讲者备注。备注只补充实际口头讲解，影响结论的真实限制与必要条件在相关观众页简明保留。

默认1280×720。目录可直达，←/→及PageUp/PageDown翻页，Home/End到首末页。备注默认收起，按钮或N主动切换，Esc收起备注与目录；展开的备注在当前页面可见，导出PNG始终隐藏。切换主题保留当前页。逐页逐句审读全部文案与备注，再查看主要信息能否迅速辨认，以及证据联系、布局重心、安全区、页脚、图内字号和条件；两种主题都检查，最终PNG使用用户选定主题，默认浅色。

## 小红书 rednote

按[小红书 Prompt](../prompts/scenes/rednote.txt)围绕明确的小主题，用少量、通俗且连贯的文字讲清核心机制。图片内完整的是所选问题的解释，不是原稿全部内容；可略难推导，不能略关键理由与适用条件。总量过大先删减与收窄非必需范围，必要解释仍放不下再按语义增页，配文仅作摘要。沿用[原小红书流程](rednote-scene.md)及原渲染器，浅暖米色academic主题、3:4、1080×1440 CSS px、DPR2。检查全部图片、公式、几何、条件、页码与手机可读性。只图请求按指定范围执行；新长文和汇报模板不覆盖其画幅、字体或视觉设置。
