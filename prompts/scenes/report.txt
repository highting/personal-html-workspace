场景 report：HTML直接展示给听众，首先优化最终页面的视觉效果，其次优化文稿的重点与详略，让听众快速形成这次汇报需要的判断。先根据实际材料、听众和用途确定汇报目的，再提炼一句话主线及支撑它的证据；未知背景和时长可作合理假设并记录，不默认等待确认。准确性、必要条件和成果归属不能为视觉效果让步；计划、理论估算、教学构造和未验证假设不能包装成实测成果。先组织讲解任务与证据，再按讲解节奏分页；一个任务可跨多页，不强求一页讲完或逐页重复结论。
按目的选择文稿主线，不机械套同一目录。成果汇报突出解决的问题、做出的改变、结果与基准比较、意义及局限；阶段进展突出相对目标已完成什么、可检查的产出、当前障碍及影响、下一步验证；方案评审突出目标与约束、候选方案的关键取舍、建议及依据、风险和验证办法；论文/技术分享突出原问题、核心思路、关键机制、作者证据与局限、对当前问题的启发。混合用途确定一个主目的，其余只保留支撑部分。分享论文与公开材料时分清原作者成果、本人的复现或分析、尚未验证的判断。有实际待决事项时明确希望听众确认什么，没有则不凑决策页或下一步。
开头尽早给出本次主判断、实际进展或待讨论问题，背景按理解该判断的需要补足；只有确实依赖前置机制时才先解释机制，并尽快接回主线。已有结果直接写对象、差异及其意义；进展页说明实际产出及边界，方案页说明推荐与取舍，知识分享页说明应理解的关系。目录和章节过渡可用主题名，内容页标题应表达本页具体信息，避免只有“数据分析”“结果讨论”或“效果显著”。每句话都应属于实际汇报，删去空泛拔高、同义复述和无新增信息的副标题；已有导航不再用正文重复目录。
数据分析优先用图表承载证据：精确值、多指标和方案对照用表格；时间或有序连续变量的变化用折线图；类别大小和排序用条形图；关系与分布按实际问题选图。围绕需要看出的差异选择图表，不能把无序类别硬连成趋势。表格保留关键列、单位与比较基准，数值对齐，以一致含义的颜色突出关键差异，辅以原值或带符号的变化量；图中直接标注关键对象、拐点或差距。相同指标使用可比较的尺度，百分比与百分点分清；缺失值不当作零，材料没有的数据不补造。颜色表示差异，不自动把高值当作好结果。图表能够说明的内容不再逐项复述成段落；没有定量证据时用必要的机制图、对照或短文字，不强造数据图。
完整汇报稿按页或页组组织，在现有工作稿中明确：听众应得到的判断、承载它的图表或必要文字、限定结论的条件、讲者的解释与衔接。观众页保留可快速读懂的主信息、证据和条件，实际会讲到的推导、背景展开与口头衔接放讲者备注；备注补足“怎么看、为什么、如何接到下一页”，不只是复述页内字句。先形成这套可审读的场景稿，再让代表页构图与页内文字共同收敛，不先写长文章再逐页塞入。正文、图注、表下注、页脚和角落小字都属于正式内容，不能夹带文档缺口解释、制作提醒、会前待办或给作者的建议，例如“资料暂缺，后续补图”“此页仅供占位”“汇报前请确认”；这些只写工作记录，也不转存到备注。缺依据就补查、缩小结论或删除不受支持的主张。真实限制和进展仍需保留，例如“目前完成方案设计，实验验证尚未开展”“仅在当前样本验证”；单位、条件、出处与必要的“机制示意”等标注靠近相关证据，不藏在备注中。
视觉重点按本页最需要传达的信息选择，可以是图表、机制图，也可以是一句或一段明确结论；不强制每页配图。重点应在短暂浏览时就能辨认，让听众迅速知道这一页说明了什么。页面设一个主要视觉焦点，其余内容支持它；影响结论的条件保持清楚可读，不能降成难辨的小字。课题名、任务描述、结论不并列成同样醒目的大标题。单独标题页形成紧凑、完整的内容组；证据页让图表取得足够空间，结论页可用醒目的短文字配必要依据，标题与内容直接关联。按内容选择单栏、主图配短文或必要的对照布局；没有右栏内容时使用完整内容区，不保留空的双栏格。流程与分工优先用文字分组、留白、细线和必要连线呈现，容器边框只用于需要表达边界的对象，不给每个角色或短句套矩形卡片；表格保留有比较含义的配色，减少整块底色。先调整分组、宽度、位置和自然换行，再处理字号，不用大字强制断行把短句挤在左侧，也不靠加套话、装饰块或无依据的图填空。留白服务于分组与重点，不能让主信息孤立在一角。具体样式见 references/visual-system.md。
用 Markdown 围栏外的独立 --- 分页，标题用 # 或 ##；复杂页可用可信 HTML 片段。复用 assets/content/report.css，以 Quarto 官方默认演示作为字体比例、留白和轻量导航的基础，沿用其封面、正文与简洁表格；可借鉴其他案例的图表标注、页型比例和逐层图解，统一到当前字体与配色，不拼接不同主题的视觉外观。参考来源见 references/template-design.md。默认纯白，页面背景只可选纯白或纸白，不提供深色或明暗样张；封面标题和导语居中，普通页标题与正文左对齐，双栏顶边对齐；不另加重复眉题、色块或图框，不默认制作超大数字页。数值进入表格或图表，比较标注紧邻数据。1280×720 固定页中，中文正文32px、标题500字重，按 Quarto 的1.6／1.3／2.5倍比例设置普通标题、小标题与封面标题；表格24–26px、条件22px，具体边距和行距见 references/visual-system.md。按中文实际字面统一校准，不直接套用英文字号，不把表格词组挤成孤字。内容超量先删冗余，再按论证关系拆页；正文与图解不得侵入页码和底部工具区，不缩成难读小字。独立标题页显式设置 cover: true。课题名不在页眉页脚重复，图面默认与页面同底色、无外框；必要图标签至少18px，条件文字清楚可读。长文图应按汇报尺寸重构，不能直接缩小。
讲者备注只保留实际讲解所需的补充表达，与正式页内文案分开；不保存当前成品的生成过程、文档缺口、审核记录或给作者的待办。工作稿用 <!-- notes: 本页讲者备注 -->，可信 HTML 用 data-notes；默认收起，通过“备注”按钮主动展开，也可用现有 N 快捷键切换，Esc收起。备注不占页面正文空间，导出PNG时始终隐藏。展开是在当前页面显示，不是独立的讲者屏，不能声称投屏时只有讲者可见。具体用法见 references/content-workflow.md。
使用 build_content.py --scene report 与 render_content.py。排版前按已确定的汇报目的审整组页面：听众能否说出主判断或当前状态、支持它的依据、它意味着什么，以及确有的待决事项；不能用“覆盖了多少知识点”代替汇报效果。再逐页逐句审核标题、副标题、正文、图中标签、图注、表下注、页脚、小字与备注：是否确为本次要表达的内容，是否有依据，是否支持重点，背景与方法是否挤占了结果、进展或取舍的篇幅。制作残留移出成品，重复解释删去，必要条件以简洁事实保留。成稿通过后，实际查看全部白底页面与PNG，并核对纸白背景切换；先检查快速浏览能否抓住重点及整组节奏，再细查数据、配色含义、布局重心、字号、安全区和全部文案。目录、翻页、背景切换与备注开合正常，PNG不含备注。视觉或内容仍有实质问题时继续修正，机器QA通过不能替代这些判断。
