场景 report：HTML 会直接展示给听众，目的是让他们快速理解我的成果：完成了什么、解决了什么问题、依据是什么、结果意味着什么。先从实际材料中提炼本次最值得传达的成果或进展，根据已知听众、背景与时长取舍；未指定时依据材料作合理假设并记录，不把确认信息变成默认等待关卡。方案、调研或阶段性工作可以作为真实进展呈现，计划、目标和未验证假设不能包装成已取得的结果。先组织讲解任务与证据，再按阅读负担和讲解节奏分页；一个任务可以连续多页，完整论证在这一组页面中成立，不强求一页讲完，也不逐页重复同一结论。
先提炼材料支持的结论及其依据，再写观众页。开头尽早给出最重要的成果及其意义，必要背景随后补足；尚无结果的方案讨论则直接说明本次提出的方案和需要形成的判断。已有结果直接写对象、差异及其意义，避免只写“数据分析”“结果讨论”或“效果显著”；方法页直述它如何支持成果或解决问题。每句话都应是本次实际会向听众表达的事实、比较、必要解释或行动。删除空泛拔高、同义复述、过渡套话及“本周进展与下周计划”这类没有新增信息的副标题；已有导航时不再用正文重复目录。
数据分析优先用图表承载证据：精确值、多指标和方案对照用表格；时间或有序连续变量的变化用折线图；类别大小和排序用条形图；关系与分布按实际问题选图。围绕需要看出的差异选择图表，不能把无序类别硬连成趋势。表格保留关键列、单位与比较基准，数值对齐，以一致含义的颜色突出关键差异，辅以原值或带符号的变化量；图中直接标注关键对象、拐点或差距。相同指标使用可比较的尺度，百分比与百分点分清；缺失值不当作零，材料没有的数据不补造。颜色表示差异，不自动把高值当作好结果。图表能够说明的内容不再逐项复述成段落；没有定量证据时用必要的机制图、对照或短文字，不强造数据图。
观众页保留简短结论、支持判断的证据与必要条件；实际会讲到的推导、背景展开与口头衔接可写入讲者备注。完整场景稿由逐页文案、已核实的图表数据与关系、必要条件和实际讲解组成，不先写长文章再逐页塞入。正文、图注、表下注、页脚和角落小字都属于正式内容，不能夹带对当前文档不足的解释、制作提醒、会前待办或给作者的建议，例如“资料暂缺，后续补图”“此页仅供占位”“汇报前请确认”；这些只写工作记录，也不转存到讲者备注。缺依据就补查、缩小结论或删除不受支持的主张，不能靠备注型小字使未完成的文档看起来可交付。真实研究限制、实际进展和计划属于汇报内容时要保留：例如“目前完成方案设计，实验验证尚未开展”放在进展页；“仅在当前样本验证”就近限定结论。必要的单位、条件、出处与“机制示意”等简短标注保留，不把它们误删，也不在每页重复写自我解释的免责文案。
视觉重点按本页最需要传达的信息选择，可以是图表、机制图，也可以是一句或一段明确结论；不强制每页配图。重点应在短暂浏览时就能辨认，让听众迅速知道这一页说明了什么。页面设一个主要视觉焦点，其余内容支持它；影响结论的条件保持清楚可读，不能降成难辨的小字。课题名、任务描述、结论不并列成同样醒目的大标题。单独标题页形成紧凑、完整的内容组；证据页让图表取得足够空间，结论页可用醒目的短文字配必要依据，标题与内容直接关联。按内容选择单栏、主图配短文或必要的对照布局；没有右栏内容时使用完整内容区，不保留空的双栏格。流程与分工优先用文字分组、留白、细线和必要连线呈现，容器边框只用于需要表达边界的对象，不给每个角色或短句套矩形卡片；表格保留有比较含义的配色，减少整块底色。先调整分组、宽度、位置和自然换行，再处理字号，不用大字强制断行把短句挤在左侧，也不靠加套话、装饰块或无依据的图填空。留白服务于分组与重点，不能让主信息孤立在一角。具体样式见 references/visual-system.md。
用 Markdown 围栏外的独立 --- 分页，标题用 # 或 ##；复杂页可用可信 HTML 片段。复用 assets/content/report.css 的数字、开放对照、轨迹和结论布局，按本页证据选择，不把所有页做成“标题＋带框图＋说明段落”。16:9 固定页为 1280×720，内容超量时先删冗余，再按论证关系拆页；正文与图解不得侵入页脚，不缩成难读小字。有独立标题页时可显式设置 cover: true。课题名不在页眉页脚重复，图面默认与页面同底色、无外框；必要图标签至少18px，条件文字保持清楚可读。长文图应按汇报尺寸重构，不能直接缩小。
讲者备注只保留实际讲解所需的补充表达，与正式页内文案分开；不保存当前成品的生成过程、文档缺口、审核记录或给作者的待办。工作稿用 <!-- notes: 本页讲者备注 -->，可信 HTML 用 data-notes；默认收起，通过“备注”按钮主动展开，也可用现有 N 快捷键切换，Esc收起。备注不占页面正文空间，导出PNG时始终隐藏。展开是在当前页面显示，不是独立的讲者屏，不能声称投屏时只有讲者可见。具体用法见 references/content-workflow.md。
使用 build_content.py --scene report 与 render_content.py。排版前先审整组页面：听众能否迅速复述主要成果、依据与意义，成果、方法、证据、实际限制和下一步是否衔接。再逐页逐句审核全部文案，包括标题、副标题、图中标签、图注、表下注、页脚、小字与讲者备注：它是否确为本次汇报要表达的内容，是否有依据，是否直接支持本页重点。制作残留移出成品，重复解释删去，必要条件以简洁的事实表述保留；不能只搜索禁用词或只检查大标题。成稿通过后，实际查看全部明暗页面与PNG，复查成品中全部文字和图表，核对视觉重点、数据、配色含义、布局重心、字号、安全区及目录、翻页、主题交互，确认备注默认收起、可展开与收起、导出不含备注。任何未处理的内容缺口或制作残留都不能因机器 QA 通过而视为完成。
